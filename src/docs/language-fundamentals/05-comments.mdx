<H2>Summary</H2>

<Prose>
  ShardScript supports single-line comments that begin with <InlineCode>//</InlineCode> and run to the end of the line. Comments are treated as trivia by the lexer, are ignored by the parser, and do not affect the generated bytecode or program execution.
</Prose>

<H2>Syntax</H2>

<CodeBlock
  code={`// This is a single-line comment. It extends to the end of the line.

public static func Main() -> void
{
    // Comments may appear on their own line.
    count: int = 0; // Or at the end of a statement.

    // x: int = 1; // A commented-out statement is not executed.
}`}

/>

<H2>Parameters / Arguments</H2>

<Prose>
  A comment takes no arguments. The text between <InlineCode>//</InlineCode> and the end of the line is arbitrary UTF-16 text, with the restriction that the comment cannot contain a line break. Anything on the same line before <InlineCode>//</InlineCode> is parsed as ordinary code.
</Prose>

<H2>Returns</H2>

<Prose>
  A comment produces no value and emits no instructions. It is discarded during lexical analysis.
</Prose>

<H2>Exceptions / Errors</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Unterminated block comment</strong> — Block comments delimited by <InlineCode>{'/*'}</InlineCode> and <InlineCode>{'*/'}</InlineCode> are not recognized. Writing <InlineCode>{'/*'}</InlineCode> starts a division expression followed by a multiplication expression, which usually produces a parse error.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Documentation comment syntax</strong> — Triple-slash <InlineCode>///</InlineCode> documentation comments are not treated specially; they are ordinary single-line comments.
  </Bullet>
</ul>

<H2>Remarks</H2>

<Prose>
  <strong>Placement.</strong> A single-line comment may appear anywhere whitespace is permitted: on its own line, after a statement, between method declarations, or inside a braced block. It cannot be inserted into the middle of a token, such as inside an identifier or a string literal.
</Prose>

<Prose>
  <strong>Nesting and multi-line.</strong> Because ShardScript has no block-comment syntax, each commented line must begin with its own <InlineCode>//</InlineCode> marker. For multi-line explanations, repeat <InlineCode>//</InlineCode> at the start of every line, or move the explanation into a documentation page.
</Prose>

<Prose>
  <strong>Commented-out code.</strong> Prefixing a statement with <InlineCode>//</InlineCode> is a common way to temporarily disable code during debugging. Be careful with braced blocks: commenting out the opening brace but not the matching closing brace can still leave valid, unintended code.
</Prose>

<Callout tone="blue">
  Comments are preserved as trivia tokens by the lexer so that tools such as formatters and language servers can access them, but they are not emitted into bytecode and have no runtime cost.
</Callout>

<H2>Examples</H2>

<Prose>
  <strong>Comment styles.</strong>
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

// Compute the square of an integer.
static func Square(x: int) -> int
{
    return x * x; // multiplication is exact for small values
}

public static func Main() -> void
{
    // This block is intentionally simple.
    value: int = 7;
    result: int = Square(value); // call the helper

    println(result); // 49
}`}
  language="csharp"
  filename="comment_styles.shard"
/>

<Prose>
  <strong>Commenting out code.</strong>
</Prose>

<CodeBlock

namespace demo;

public static func Main() -> void

    // a = 2; // This assignment is disabled.

    // The entire block below is commented out.
    // if (a > 0)
    // {
    //     println("positive");
    // }

    println(a); // 1
}`}

<H2>Source</H2>

<Prose>
  Single-line comment tokenization is implemented in the ShardScript compiler. The lexer classifies <InlineCode>//</InlineCode> as <InlineCode>TokenType::Trivia</InlineCode> and consumes characters until the next line break in <InlineCode>ShardScript/ShardScript/src/lexical/LexicalAnalyzer.cpp</InlineCode>.
</Prose>
