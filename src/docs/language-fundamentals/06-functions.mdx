<H2>Summary</H2>

<Prose>
  A <strong>function</strong> in ShardScript is a named, reusable block of code declared with the <InlineCode>func</InlineCode> keyword. Functions receive typed parameters, optionally return a value, and are invoked by writing the function name followed by a parenthesized argument list.
</Prose>

<H2>Syntax</H2>

<Prose>
  A function declaration consists of optional modifiers, the <InlineCode>func</InlineCode> keyword, an identifier, an optional generic parameter list, a parenthesized parameter list, a return type, and a braced body.
</Prose>

<CodeBlock
  code={`[access] [static] func Name<T>(parameters) -> ReturnType
{
    // body
}`}
  language="csharp"
  filename="function_syntax.shard"
/>

<Prose>
  A function is called by writing its name followed by a parenthesized argument list. Generic arguments are supplied inside angle brackets when they cannot be inferred.
</Prose>

<CodeBlock
  code={`// Call a function with explicit arguments.
result: int = Add(2, 3);

// Call a generic function with an explicit type argument.
swapped: int[] = Swap<int>(1, 2);

// Call a static function through its declaring type.
id: int = IdGenerator.Generate();`}

<H2>Parameters / Arguments</H2>

<Prose>
  Parameters are declared positionally with explicit type annotations. Arguments at the call site are matched by position and checked for type compatibility. The first parameter of an instance method is an implicit <InlineCode>this</InlineCode> reference, but ordinary top-level and static functions have no implicit receiver.
</Prose>

<H2>Exceptions / Errors</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Missing return type</strong> — Every function except constructors (<InlineCode>init</InlineCode>) must specify <InlineCode>-&gt; ReturnType</InlineCode>.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Return type mismatch</strong> — Returning an <InlineCode>int</InlineCode> from a function declared <InlineCode>-&gt; string</InlineCode> fails semantic analysis.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Unreachable end of non-void function</strong> — If a non-void function can complete without a <InlineCode>return</InlineCode> statement, the compiler reports an error.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Argument count mismatch</strong> — Calling a function with too many or too few arguments is a compile-time error.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Argument type mismatch</strong> — An argument that is not assignable to the corresponding parameter type is rejected at compile time.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Ambiguous overload</strong> — Two functions in the same scope with the same name and identical parameter lists produce a duplicate-symbol error.
  </Bullet>
</ul>

<H2>Remarks</H2>

<Prose>
  <strong>Functions versus methods.</strong> This page describes the core syntax shared by every callable named block. A function declared at namespace scope is a top-level function; a function declared inside a class, struct, or interface is a method. Methods are covered in the Object-Oriented Programming section because they interact with instances, access modifiers, and inheritance semantics.
</Prose>

<Prose>
  <strong>Static versus instance.</strong> A function marked <InlineCode>static</InlineCode> has no implicit <InlineCode>this</InlineCode> parameter and is invoked through its declaring type or namespace. An instance method omits <InlineCode>static</InlineCode> and receives the receiver object as the first evaluation-stack slot.
</Prose>

<Prose>
  <strong>Overloading.</strong> Multiple functions may share the same name as long as their parameter lists differ in arity or type. Return type alone does not distinguish overloads. Overload resolution is performed at compile time and prefers exact type matches.
</Prose>

<Prose>
  <strong>Generic functions.</strong> A function can declare its own type parameters independent of any enclosing type. Type arguments may be supplied explicitly at the call site (<InlineCode>Swap&lt;int&gt;(a, b)</InlineCode>) or, in many cases, inferred from the argument types.
</Prose>

<Prose>
  <strong>Call dispatch.</strong> The compiler resolves a function call to a specific method symbol at compile time. Static and top-level calls emit <InlineCode>CALLSTATICMETHODSYMBOL</InlineCode>; instance calls emit <InlineCode>CALLMETHODSYMBOL</InlineCode>. The VM pushes the arguments in declaration order, executes the method body, and leaves the return value on the caller's evaluation stack.
</Prose>

<Callout tone="blue">
  Functions are not the same as delegates. A function declaration introduces a method symbol; a delegate is a separate callable value type. To store a function in a variable, pass it as an argument, or return it from another function, use a delegate. See the Delegates and Lambda Expressions articles for details.
</Callout>

<Prose>
  <strong>Generic function.</strong>
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

static func Swap<T>(a: T, b: T) -> T[]
{
    pair: T[] = new T[2];
    pair[0] = b;
    pair[1] = a;
    return pair;
}

public static func Main() -> void
{
    swapped: int[] = Swap<int>(1, 2);
    println(swapped[0]);   // 2
    println(swapped[1]);   // 1
}`}

<Prose>
  <strong>Static function with type-level state.</strong>
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public class IdGenerator
{
    private static NextId: int;

    public static func Generate() -> int
    {
        id: int = IdGenerator.NextId;
        IdGenerator.NextId = IdGenerator.NextId + 1;
        return id;
    }
}

public static func Main() -> void
{
    println(IdGenerator.Generate());   // 0
    println(IdGenerator.Generate());   // 1
    println(IdGenerator.Generate());   // 2
}`}
