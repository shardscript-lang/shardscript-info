<Prose>
  This tutorial walks through building a minimal native C++ library for the ShardScript runtime as a
  completely separate project. By the end you will have a compiled shared library —{' '}
  <InlineCode>my_shard_library</InlineCode> — in its own directory <InlineCode>my-shard-library</InlineCode>,
  exposing a static class <InlineCode>MyType</InlineCode> with a <InlineCode>DoWork</InlineCode> method,
  and a ShardScript program that calls it.
</Prose>

<H2>Prerequisites</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    A working C++20 toolchain and CMake 3.20 or later.
  </Bullet>
  <Bullet>
    A pre-built ShardScript runtime shared library and its headers. The headers are in{' '}
    <InlineCode>ShardScript/include</InlineCode> and the runtime binary is next to the interpreter.
  </Bullet>
  <Bullet>
    The <InlineCode>shard</InlineCode> interpreter available on your PATH or in your ShardScript
    build output directory.
  </Bullet>
  <Bullet>
    Basic familiarity with ShardScript namespaces, classes, and methods.
  </Bullet>
</ul>

<H2>Scenario</H2>

<Prose>
  You want to extend the runtime with a small native library built outside the ShardScript
  repository. The library will contain two C++ source files: one that holds the callback bodies and
  one that registers the metadata and symbols. You will build a shared library manually with CMake,
  then load it from a ShardScript program using the <InlineCode>-l</InlineCode> flag.
</Prose>

<H2>Step-by-Step Instructions</H2>

<Prose>
  <strong>1. Create the project directory.</strong>
</Prose>

<Prose>
  Make a new directory anywhere on your filesystem. This tutorial uses{' '}
  <InlineCode>my-shard-library/</InlineCode> next to the ShardScript repository.
</Prose>

<CodeBlock
  code={`mkdir my-shard-library
cd my-shard-library`}
  language="bash"
/>

<DocsTable
  headers={['Path', 'Purpose']}
  rows={[
    ['my-shard-library/CMakeLists.txt', 'CMake build script that produces the shared library.'],
    ['my-shard-library/callbacks.cpp', 'Callback bodies that run when ShardScript invokes the library.'],
    ['my-shard-library/library.cpp', 'Library metadata and symbol registration.'],
    ['my-shard-library/app.shard', 'ShardScript program that consumes the library.'],
  ]}
/>

<Prose>
  <strong>2. Write the callback bodies.</strong>
</Prose>

<Prose>
  Open <InlineCode>callbacks.cpp</InlineCode> and include the ShardScript runtime headers. The
  callback reads the integer argument, doubles it, and returns the result through the garbage
  collector. Keeping callbacks in a separate file is not required, but it mirrors how larger native
  libraries organize implementation code away from registration code.
</Prose>

<CodeBlock
  code={`#include <shard/ShardScriptLIB.hpp>
#include <shard/runtime/ObjectInstance.hpp>
#include <shard/runtime/MethodCallState.hpp>

using namespace shard;

ObjectInstance* MyLibrary_DoWork(const CallState& context)
{
    // Instance methods receive 'this' as Args[0]; for a static method the first
    // argument is the first real parameter passed from ShardScript.
    std::int64_t value = context.Args[0]->AsInteger();

    // The tutorial example simply doubles the input so the result is easy to verify.
    std::int64_t result = value * 2;

    return context.Collector.FromValue(result);
}`}
  language="cpp"
  filename="callbacks.cpp"
/>

<Prose>
  <strong>3. Register the library metadata and symbols.</strong>
</Prose>

<Prose>
  Create <InlineCode>library.cpp</InlineCode>. Include the ShardScript authoring headers,
  forward-declare the callback defined in <InlineCode>callbacks.cpp</InlineCode>, then use{' '}
  <InlineCode>SHARDLIB_GETMETADATA</InlineCode> to describe the library and{' '}
  <InlineCode>SHARDLIB_ENTRYPOINT</InlineCode> to register the namespace, class, and method.
</Prose>

<CodeBlock
  code={`#include <shard/ShardScriptLIB.hpp>
#include <shard/CompilationContext.hpp>
#include <shard/semantic/SymbolBuilder.hpp>

using namespace shard;

// Callbacks defined in callbacks.cpp.
ObjectInstance* MyLibrary_DoWork(const CallState& context);

SHARDLIB_GETMETADATA
{
    lib.Name        = L"shard.mylibrary";
    lib.Description = L"A minimal native shard library";
    lib.Version     = L"1.0.0";
}

SHARDLIB_ENTRYPOINT
{
    SymbolBuilder<NamespaceSymbol> myNamespace(context, L"mylibrary");

    // Register a static class so it can be called through the type name.
    myNamespace.AddClass(L"MyType", ACS_PUBLIC, LINK_STATIC, [](SymbolBuilder<ClassSymbol> type)
    {
        type.AddMethod(L"DoWork", TYPE_INT, LINK_STATIC)
            .AddParameter(L"value", TYPE_INT)
            .SetCallback(&MyLibrary_DoWork);
    });
}`}
  language="cpp"
  filename="library.cpp"
/>

<Callout tone="blue" title="Why LINK_STATIC for the class">
  A class registered with <InlineCode>LINK_STATIC</InlineCode> behaves like a static class in
  ShardScript: it cannot be instantiated and its members are reached through the type name. This
  matches the tutorial call site <InlineCode>MyType.DoWork(7)</InlineCode>.
</Callout>

<Prose>
  <strong>4. Add a CMake build script.</strong>
</Prose>

<Prose>
  The CMakeLists.txt is a normal shared-library target. It points to the ShardScript include
  directory and links the pre-built ShardScript runtime library. Adjust the library and include
  paths to match where you built or installed ShardScript.
</Prose>

<CodeBlock
  code={`cmake_minimum_required(VERSION 3.20)
project(MyShardLibrary CXX)

set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# Path to the ShardScript checkout or installation.
set(SHARDSCRIPT_ROOT "\${CMAKE_CURRENT_SOURCE_DIR}/../ShardScript"
    CACHE PATH "Root of the ShardScript repository or install prefix")

# ShardScript runtime library location.
find_library(SHARDSCRIPT_LIB
    NAMES ShardScript libShardScript
    PATHS "\${SHARDSCRIPT_ROOT}/build/bin" "\${SHARDSCRIPT_ROOT}/lib"
    NO_DEFAULT_PATH
    REQUIRED
)

add_library(my_shard_library SHARED
    library.cpp
    callbacks.cpp
)

set_target_properties(my_shard_library PROPERTIES
    WINDOWS_EXPORT_ALL_SYMBOLS ON
)

target_include_directories(my_shard_library PRIVATE "\${SHARDSCRIPT_ROOT}/ShardScript/include")
target_link_libraries(my_shard_library PRIVATE \${SHARDSCRIPT_LIB})`}
  language="cmake"
  filename="CMakeLists.txt"
/>

<Prose>
  <strong>5. Build the library.</strong>
</Prose>

<Prose>
  Configure and build from the project directory.
</Prose>

<CodeBlock
  code={`cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel`}
  language="bash"
/>

<Prose>
  The build emits a shared library in the <InlineCode>build/</InlineCode> directory:
</Prose>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    On Windows: <InlineCode>build/my_shard_library.dll</InlineCode>
  </Bullet>
  <Bullet>
    On Linux: <InlineCode>build/libmy_shard_library.so</InlineCode>
  </Bullet>
  <Bullet>
    On macOS: <InlineCode>build/libmy_shard_library.dylib</InlineCode>
  </Bullet>
</ul>

<Prose>
  <strong>6. Write a ShardScript program that consumes the library.</strong>
</Prose>

<Prose>
  Create <InlineCode>app.shard</InlineCode> in the project directory. Import the{' '}
  <InlineCode>mylibrary</InlineCode> namespace and call the static method.
</Prose>

<CodeBlock
  code={`using stdio;
using mylibrary;

namespace demo;

public static func Main() -> void
{
    result: int = MyType.DoWork(7);
    println("Result: " + result);
}`}
  language="csharp"
  filename="app.shard"
/>

<Prose>
  <strong>7. Run the program and load the shard explicitly.</strong>
</Prose>

<Prose>
  The interpreter does not auto-load shards that live outside its own system directory, so pass the
  compiled shared library with the <InlineCode>-l</InlineCode> flag.
</Prose>

<CodeBlock
  code={`# Windows
shard app.shard -l build/my_shard_library.dll

# Linux
shard app.shard -l build/libmy_shard_library.so

# macOS
shard app.shard -l build/libmy_shard_library.dylib`}
  language="bash"
/>

<H2>Expected Output</H2>

<Prose>
  When the program runs, the native callback receives <InlineCode>7</InlineCode>, doubles it, and the
  managed program prints:
</Prose>

<CodeBlock
  code={`Result: 14`}
  language="text"
/>

<Callout tone="green" title="Success criteria">
  If you see <InlineCode>Result: 14</InlineCode>, the library compiled correctly, the runtime loaded
  it, and the method registration resolved the <InlineCode>MyType.DoWork</InlineCode> symbol.
</Callout>

    Declare dependencies in <InlineCode>SHARDLIB_GETMETADATA</InlineCode> when your library relies on
    other shards.
  </Bullet>
  <Bullet>

    <InlineCode>library-building/reading-arguments</InlineCode>.
