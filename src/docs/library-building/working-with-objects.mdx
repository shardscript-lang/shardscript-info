<Prose>
  This how-to explains how to allocate, inspect, and mutate ShardScript objects from inside native C++
  callbacks. You will register a concrete class with instance fields, read and write those fields through
  <InlineCode>ObjectInstance::GetField</InlineCode> and <InlineCode>SetField</InlineCode>, allocate
  constructed generic instances with <InlineCode>AllocateGeneric</InlineCode>, use{' '}
  <InlineCode>getInfo</InlineCode> and <InlineCode>getShape</InlineCode> to recover runtime type
  information, and use the convenience helpers in{' '}
  <InlineCode>{'<shard/runtime/NativeHelpers.hpp>'}</InlineCode> for construction, method calls, field
  access, and property access.
</Prose>

<H2>Prerequisites</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    A C++20 toolchain and a project that links the ShardScript runtime shared library.
  </Bullet>
  <Bullet>
    The ShardScript headers on your include path, especially{' '}
    <InlineCode>ShardScript.hpp</InlineCode>, <InlineCode>shard/runtime/ObjectInstance.hpp</InlineCode>,{' '}
    <InlineCode>shard/runtime/NativeHelpers.hpp</InlineCode>, and{' '}
    <InlineCode>shard/semantic/SymbolFactory.hpp</InlineCode>.
  </Bullet>
  <Bullet>
    Familiarity with the two exported symbols, <InlineCode>SHARDLIB_GETMETADATA</InlineCode> and{' '}
    <InlineCode>SHARDLIB_ENTRYPOINT</InlineCode>, and the <InlineCode>SymbolBuilder</InlineCode> fluent
    registration API.
  </Bullet>
  <Bullet>
    Basic understanding of ShardScript generic syntax from the caller side.
  </Bullet>
</ul>

<H2>Goal</H2>

<Prose>
  Build a small native library called <InlineCode>shard.objectsdemo</InlineCode> that exposes:
</Prose>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    A <InlineCode>Counter</InlineCode> class with an integer field and an instance method that
    increments it.
  </Bullet>
  <Bullet>
    A <InlineCode>Cell&lt;T&gt;</InlineCode> generic class with a single field and methods to set and
    get the value.
  </Bullet>
  <Bullet>
    A helper that prints the concrete type arguments of a generic instance by inspecting its shape.
  </Bullet>
</ul>

<H2>Step-by-Step Instructions</H2>

<Prose>
  <strong>1. Create the library source file.</strong>
</Prose>

<Prose>
  A native library is any shared library that exports <InlineCode>ShardLib_GetMetadata</InlineCode> and{' '}
  <InlineCode>ShardLib_EntryPoint</InlineCode>. It can be built from one source file or many, inside the
  framework tree or in a separate project. Create a single C++ source file for this demo.
</Prose>

<CodeBlock
  code={`#include <ShardScript.hpp>
#include <shard/runtime/ObjectInstance.hpp>
#include <shard/runtime/MethodCallState.hpp>
#include <shard/runtime/NativeHelpers.hpp>
#include <shard/semantic/SymbolBuilder.hpp>
#include <shard/semantic/SymbolFactory.hpp>

using namespace shard;`}
  language="cpp"
  filename="objects_demo.shard.cpp"
/>

<Prose>
  <strong>2. Capture the symbols you will need at runtime.</strong>
</Prose>

<Prose>
  Field access uses the <InlineCode>SlotIndex</InlineCode> that <InlineCode>AddField</InlineCode>
  assigns at registration time. Generic allocation needs the raw class definition and its type parameter.
  Store these as static pointers so the callbacks can reach them later.
</Prose>

<CodeBlock
  code={`// Concrete type symbols.
static ClassSymbol* counterClass = nullptr;
static MethodSymbol* counterIncrementMethod = nullptr;
static FieldSymbol* counter_valueField = nullptr;

// Generic Cell<T> symbols.
static ClassSymbol* cellClass_raw = nullptr;
static TypeParameterSymbol* cell_T = nullptr;
static FieldSymbol* cell_valueField = nullptr;`}
  language="cpp"
  filename="objects_demo.shard.cpp"
/>

<Prose>
  <strong>3. Register the <InlineCode>Counter</InlineCode> class and its methods.</strong>
</Prose>

<Prose>
  Use <InlineCode>LINK_INSTANCE</InlineCode> for the class so ShardScript can create instances of it.
  The constructor callback receives the newly allocated instance as <InlineCode>context.Args[0]</InlineCode>{' '}
  and must return that same instance.
</Prose>

<CodeBlock
  code={`static ObjectInstance* Counter_Init(const CallState& context)
{
    ObjectInstance* self = context.Args[0];
    self->SetField(counter_valueField->SlotIndex, context.Collector.FromValue(0));
    return self;
}

static ObjectInstance* Counter_Increment(const CallState& context)
{
    ObjectInstance* self = context.Args[0];

    std::int64_t current = self->GetField(counter_valueField->SlotIndex)->AsInteger();
    std::int64_t next = current + 1;

    self->SetField(counter_valueField->SlotIndex, context.Collector.FromValue(next));
    return nullptr;
}

static ObjectInstance* Counter_GetValue(const CallState& context)
{
    ObjectInstance* self = context.Args[0];
    ObjectInstance* value = self->GetField(counter_valueField->SlotIndex);
    return value;
}`}
  language="cpp"
  filename="objects_demo.shard.cpp"
/>

<CodeBlock
  code={`static void RegisterCounter(SymbolBuilder<NamespaceSymbol>& ns)
{
    ns.AddClass(L"Counter", ACS_PUBLIC, LINK_INSTANCE, [](SymbolBuilder<ClassSymbol> cls)
    {
        counterClass = cls.Get();
        counter_valueField = cls.AddField(L"_value", TYPE_INT, LINK_INSTANCE, ACS_PRIVATE).Get();

        cls.AddInit()
            .SetCallback(&Counter_Init);

        counterIncrementMethod = cls.AddMethod(L"Increment", TYPE_VOID, LINK_INSTANCE)
            .SetCallback(&Counter_Increment)
            .Get();

        cls.AddMethod(L"GetValue", TYPE_INT, LINK_INSTANCE)
            .SetCallback(&Counter_GetValue);
    });
}`}
  language="cpp"
  filename="objects_demo.shard.cpp"
/>

<Callout tone="blue" title="Why capture FieldSymbol*">
  The runtime assigns each field a stable slot number, but the exact number depends on registration order
  and base types. Always store the returned <InlineCode>FieldSymbol*</InlineCode> and use{' '}
  <InlineCode>SlotIndex</InlineCode> rather than hard-coding an integer offset.
</Callout>

<Prose>
  <strong>4. Register the generic <InlineCode>Cell&lt;T&gt;</InlineCode> class.</strong>
</Prose>

<Prose>
  A generic class needs a type parameter before its fields or method parameters can reference it. Use{' '}
  <InlineCode>AddTypeParameter</InlineCode> to introduce <InlineCode>T</InlineCode>, then use{' '}
  <InlineCode>SymbolFactory</InlineCode> to build array or generic field types when necessary.
</Prose>

<CodeBlock
  code={`static ObjectInstance* Cell_Init(const CallState& context)
{
    ObjectInstance* self = context.Args[0];

    // The concrete substitution for T is the first type argument on the current frame.
    TypeSymbol* concreteT = context.Frame->TypeArguments[0];

    // For a reference type T, default-initialize the field to null.
    self->SetField(cell_valueField->SlotIndex, GarbageCollector::NullInstance);
    return self;
}

static ObjectInstance* Cell_SetValue(const CallState& context)
{
    ObjectInstance* self = context.Args[0];
    ObjectInstance* value = context.Args[1];
    self->SetField(cell_valueField->SlotIndex, value);
    return nullptr;
}

static ObjectInstance* Cell_GetValue(const CallState& context)
{
    ObjectInstance* self = context.Args[0];
    return self->GetField(cell_valueField->SlotIndex);
}`}
  language="cpp"
  filename="objects_demo.shard.cpp"
/>

<CodeBlock
  code={`static void RegisterCell(SymbolBuilder<NamespaceSymbol>& ns)
{
    ns.AddClass(L"Cell", ACS_PUBLIC, LINK_INSTANCE, [](SymbolBuilder<ClassSymbol> cls)
    {
        cellClass_raw = cls.Get();
        cell_T = cls.AddTypeParameter(L"T").Get();
        cell_valueField = cls.AddField(L"_value", cell_T, LINK_INSTANCE, ACS_PRIVATE).Get();

        cls.AddInit()
            .SetCallback(&Cell_Init);

        cls.AddMethod(L"SetValue", TYPE_VOID, LINK_INSTANCE)
            .AddParameter(L"value", cell_T)
            .SetCallback(&Cell_SetValue);

        cls.AddMethod(L"GetValue", cell_T, LINK_INSTANCE)
            .SetCallback(&Cell_GetValue);
    });
}`}
  language="cpp"
  filename="objects_demo.shard.cpp"
/>

<Prose>
  <strong>5. Allocate a constructed generic instance from another callback.</strong>
</Prose>

<Prose>
  <InlineCode>GarbageCollector::AllocateGeneric</InlineCode> creates an instance of the raw generic
  definition with concrete type arguments substituted. Use it when you need to manufacture a generic object
  inside native code rather than returning it from a constructor.
</Prose>

<CodeBlock
  code={`static ObjectInstance* MakeIntCell(const CallState& context)
{
    // Allocate Cell<int> directly.
    ObjectInstance* cell = context.Collector.AllocateGeneric(cellClass_raw, { TYPE_INT });

    // Initialize the backing field so the object is in a valid state.
    cell->SetField(cell_valueField->SlotIndex, context.Collector.FromValue(42));
    return cell;
}`}
  language="cpp"
  filename="objects_demo.shard.cpp"
/>

<Callout tone="amber" title="AllocateGeneric vs AllocateInstance">
  Always use <InlineCode>AllocateGeneric</InlineCode> for generic classes.{' '}
  <InlineCode>AllocateInstance</InlineCode> creates an instance of the raw definition without substituting
  type arguments, which leaves the object with an incorrect shape and breaks field layout for value-type
  type arguments.
</Callout>

<Prose>
  <strong>6. Inspect runtime type information with <InlineCode>getInfo</InlineCode> and{' '}
  <InlineCode>getShape</InlineCode>.</strong>
</Prose>

<Prose>
  <InlineCode>getInfo</InlineCode> returns the generic class definition symbol. The concrete type arguments
  live on <InlineCode>{'getShape()->GenericArguments'}</InlineCode>. Use this when a callback receives a generic
  object and must reason about the actual substitution.
</Prose>

<CodeBlock
  code={`static ObjectInstance* InspectCell(const CallState& context)
{
    ObjectInstance* cell = context.Args[0];

    ClassSymbol* definition = cell->getInfo();
    TypeSymbol* concreteT = nullptr;

    if (cell->getShape() != nullptr && !cell->getShape()->GenericArguments.empty())
    {
        concreteT = cell->getShape()->GenericArguments[0];
    }

    std::wstring message = L"definition=" + definition->Name;
    if (concreteT != nullptr)
    {
        message += L", T=" + concreteT->Name;
    }

    return context.Collector.FromValue(message);
}`}
  language="cpp"
  filename="objects_demo.shard.cpp"
/>

<Prose>
  <strong>7. Wire everything together in the entry point.</strong>
</Prose>

<CodeBlock
  code={`SHARDLIB_GETMETADATA
{
    lib.Name        = L"shard.objectsdemo";
    lib.Description = L"ObjectInstance, fields, and generic allocation demo";
    lib.Version     = L"1.0.0";
}

SHARDLIB_ENTRYPOINT
{
    SymbolBuilder<NamespaceSymbol> ns(context, L"objectsdemo");

    RegisterCounter(ns);
    RegisterCell(ns);

    SymbolFactory factory(context.GetSemanticModel().Table.get());

    ns.AddMethod(L"MakeIntCell", TYPE_ANY, LINK_STATIC, ACS_PUBLIC)
        .SetCallback(&MakeIntCell);

    ns.AddMethod(L"InspectCell", TYPE_STRING, LINK_STATIC, ACS_PUBLIC)
        .AddParameter(L"cell", factory.GenericType(cellClass_raw, { { L"T", cell_T } }))
        .SetCallback(&InspectCell);
}`}
  language="cpp"
  filename="objects_demo.shard.cpp"
/>

<Callout tone="blue" title="Registering generic method parameters">
  Use <InlineCode>SymbolFactory::GenericType</InlineCode> to describe an open generic parameter type such
  as <InlineCode>Cell&lt;T&gt;</InlineCode> at registration time. Pass the raw class and a list of its type
  parameters in the same order as <InlineCode>AddTypeParameter</InlineCode>.
</Callout>

<Prose>
  <strong>8. Build the shared library.</strong>
</Prose>

<Prose>
  Link against the ShardScript runtime shared library and include <InlineCode>ShardScript/include</InlineCode>.
  The exact command depends on your build system; a minimal CMake target looks like this.
</Prose>

<CodeBlock
  code={`add_library(objects_demo SHARED objects_demo.shard.cpp)

target_include_directories(objects_demo PRIVATE "\${SHARDSCRIPT_ROOT}/ShardScript/include")
target_link_libraries(objects_demo PRIVATE ShardScript)`}

<H2>Convenience helpers from NativeHelpers.hpp</H2>

<Prose>
  The helpers in <InlineCode>{'<shard/runtime/NativeHelpers.hpp>'}</InlineCode> wrap the low-level object
  API so callbacks can construct instances, invoke methods, and read or write fields and properties without
  manually managing argument arrays or reference counts. They are ordinary inline functions, so including the
  header is enough; no extra library link is required.
</Prose>

<DocsTable
  headers={['Helper', 'Purpose']}
  rows={[
    [<InlineCode>NewObject</InlineCode>, 'Allocates an instance and invokes a constructor, returning an owning reference.'],
    [<InlineCode>CallMethod</InlineCode>, 'Invokes a static or instance method with an initializer list of arguments.'],
    [<InlineCode>GetField</InlineCode>, 'Reads a field value through its FieldSymbol.'],
    [<InlineCode>SetField</InlineCode>, 'Writes a field value through its FieldSymbol.'],
    [<InlineCode>GetProperty</InlineCode>, 'Invokes a property getter.'],
    [<InlineCode>SetProperty</InlineCode>, 'Invokes a property setter.'],
  ]}
/>

<Prose>
  For example, the following callback manufactures a <InlineCode>Counter</InlineCode>, increments it twice
  through its instance method, and returns the final value object. The helper handles the argument vector,
  the <InlineCode>this</InlineCode> pointer, and reference counting during the constructor call.
</Prose>

<CodeBlock
  code={`#include <shard/runtime/NativeHelpers.hpp>

static ObjectInstance* ManufactureAndIncrement(const CallState& context)
{
    // Allocate and construct Counter with the parameterless constructor.
    ObjectInstance* counter = NewObject(context, counterClass);

    // Invoke Counter.Increment() twice via the registered method symbol.
    CallMethod(context, counterIncrementMethod, counter);
    CallMethod(context, counterIncrementMethod, counter);

    // Return the value field directly; the caller receives a borrowed reference.
    return GetField(counter, counter_valueField);
}`}
  language="cpp"
  filename="objects_demo.shard.cpp"
/>

<Callout tone="blue" title="Reference counting with NewObject">
  <InlineCode>NewObject</InlineCode> returns an object whose reference count is already 1. If you do not
  store it in a field, return it, or hand it to the garbage collector before the callback exits, decrement
  the reference with <InlineCode>DecrementReference()</InlineCode> to avoid leaking the instance.
</Callout>

<H2>Troubleshooting</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong>Field reads return stale or garbage values.</strong> Verify that you stored the{' '}
    <InlineCode>FieldSymbol*</InlineCode> returned by <InlineCode>AddField</InlineCode> and that you use{' '}
    <InlineCode>{'field->SlotIndex'}</InlineCode> for both <InlineCode>GetField</InlineCode> and{' '}
    <InlineCode>SetField</InlineCode>.
  </Bullet>
  <Bullet>
    <strong>Generic instance behaves as if its type arguments are missing.</strong> Make sure you allocated
    it with <InlineCode>{'AllocateGeneric(rawClass, { concreteT })'}</InlineCode>, not{' '}
    <InlineCode>AllocateInstance(rawClass)</InlineCode>.
  </Bullet>
  <Bullet>
    <strong><InlineCode>getInfo()</InlineCode> returns the raw definition instead of the constructed
    type.</strong> This is expected. For concrete type arguments read{' '}
    <InlineCode>{'instance->getShape()->GenericArguments'}</InlineCode> instead.
  </Bullet>
  <Bullet>
    <strong>Null reference when reading a field.</strong> Initialize fields in the constructor or
    immediately after <InlineCode>AllocateGeneric</InlineCode>. Reference-typed fields default to null if
    left untouched.
  </Bullet>
  <Bullet>
    <strong>Callback receives the wrong generic type argument.</strong> Read{' '}
    <InlineCode>{'context.Frame->TypeArguments'}</InlineCode> in the same order as the{' '}
    <InlineCode>AddTypeParameter</InlineCode> calls. The first added parameter is at index 0.
  </Bullet>
</ul>
