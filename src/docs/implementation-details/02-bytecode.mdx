<H2>Summary</H2>

<Prose>
  ShardScript compiles methods into a flat stream of 16-bit opcodes followed by inline operands. The
  bytecode, together with type shapes and a string pool, forms the <InlineCode>ProgramVirtualImage</InlineCode>
  that the virtual machine executes.
</Prose>

<H2>Syntax</H2>

<Prose>
  Each instruction is an <InlineCode>OpCode</InlineCode> value followed by zero or more operands:
</Prose>

<DocsTable
  headers={['Operand kind', 'Description']}
  rows={[
    ['Immediate literal', 'An integer, double, or boolean encoded inline.'],
    ['Local slot index', 'The zero-based slot of a local variable in the current frame.'],
    ['Jump offset', 'A signed byte or instruction offset for branch instructions.'],
    ['String pool index', 'An index into the module-wide string pool.'],
    ['Symbol reference', 'A resolved TypeSymbol, MethodSymbol, FieldSymbol, or ConstructorSymbol.'],
  ]}
/>

<H2>Parameters / Arguments</H2>

<Prose>
  Operands are decoded by the VM&apos;s instruction decoder. The size and interpretation of operands are
  fixed by the opcode definition. For example, <InlineCode>LOADCONST_INTEGER64</InlineCode> is followed by an
  8-byte signed integer, while <InlineCode>JUMP</InlineCode> is followed by a 4-byte offset.
</Prose>

<H2>Returns</H2>

<Prose>
  Most opcodes leave a value on the evaluation stack, store a value into a local or field, or alter control
  flow. The <InlineCode>RETURN</InlineCode> opcode pops the current frame and leaves the return value on the
  caller&apos;s evaluation stack.
</Prose>

<H2>Exceptions / Errors</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Invalid opcode.</strong> A corrupted or misaligned bytecode stream
    may produce an opcode the VM does not recognise.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Stack underflow.</strong> An instruction that expects operands may
    fail if the evaluation stack does not contain enough values.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Type mismatch.</strong> Although the compiler prevents this, a
    malformed image may pass the wrong type to a primitive operation.
  </Bullet>
</ul>
