<Prose>
  ShardScript implements <InlineCode>async</InlineCode> / <InlineCode>await</InlineCode> through a
  compiler transformation called <strong>async state-machine lowering</strong>. Instead of generating
  bytecode for the async method directly, the compiler emits a compiler-generated class that
  remembers where execution was suspended, hoists local variables into fields, and resumes execution
  later via a generated <InlineCode>MoveNext</InlineCode> method. The VM itself has no
  <InlineCode>AWAIT</InlineCode> opcode — the entire cooperative-multitasking story is expressed with
  ordinary method calls, fields, jumps, and the libuv event loop.
</Prose>

<H2>Introduction</H2>

<Prose>
  Writing an async method feels sequential: you call an API, use <InlineCode>await</InlineCode> to wait
  for it, and continue on the next line. Under the hood, however, the original stack frame is
  destroyed when the method suspends. To make variables and control flow survive across suspension
  points, the compiler rewrites the method into a <strong>state machine</strong> before bytecode is
  emitted.
</Prose>

<Prose>
  This article explains that rewrite: the three compiler passes that produce the state machine, the
  fields the generated class carries, the <InlineCode>MoveNext</InlineCode> dispatch loop, and the
  bytecode sequence emitted around every <InlineCode>await</InlineCode>. Understanding lowering helps
  you predict which variables are allocated, why exceptions behave the way they do across awaits,
  and which async constructs are currently supported.
</Prose>

<H2>What it is</H2>

<Prose>
  When the parser sees an <InlineCode>async func</InlineCode> with a return type of
  <InlineCode>Task</InlineCode> or <InlineCode>ValueTask&lt;T&gt;</InlineCode>, it marks the method
  symbol as async. The compiler then runs <InlineCode>AsyncStateMachineLowering</InlineCode>, a
  three-pass pipeline that replaces the original method body with:
</Prose>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    A <strong className="text-text-primary">factory method</strong> with the original signature that
    creates the state machine, roots its task, and kicks off the first segment.
  </Bullet>
  <Bullet>
    A compiler-generated <strong className="text-text-primary">state-machine class</strong> whose
    fields hold the suspended state, the returned task, lifted parameters/locals, and one awaiter
    field per await site.
  </Bullet>
  <Bullet>
    A <strong className="text-text-primary">MoveNext</strong> method that switches on an integer
    <InlineCode>_state</InlineCode> field and runs the code between awaits.
  </Bullet>
</ul>

<DocsTable
  headers={['Pass', 'Phase', 'Class', 'Responsibility']}
  rows={[
    ['1', 'Prepare', 'AsyncHoistingPass', 'Rewrites nested awaits into top-level variable or expression statements so lowering can split the body at await boundaries.'],
    ['2', 'Prepare', 'AsyncAnalysisPass', 'Scans the rewritten body for await sites and builds the state-machine class, its fields, and the MoveNext symbol.'],
    ['3', 'Emit', 'AsyncEmissionPass', 'Emits bytecode for the state-machine constructor, the factory body, and the segmented MoveNext body.'],
  ]}
/>

<Prose>
  Passes 1 and 2 run during <InlineCode>Prepare</InlineCode>, before slot layout, so the generated
  fields receive correct offsets. Pass 3 runs during <InlineCode>Emit</InlineCode>, after layout, so
  every <InlineCode>LOADFIELD</InlineCode> / <InlineCode>STOREFIELD</InlineCode> uses the final slot
  indices.
</Prose>

<H2>When to use it</H2>

<Prose>
  You do not invoke lowering manually. It runs automatically for every method marked
  <InlineCode>async</InlineCode>. The concept matters when:
</Prose>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    You are writing non-trivial async code and need to know which variables survive an
    <InlineCode>await</InlineCode> and which constructs are not yet supported.
  </Bullet>
  <Bullet>
    You are reading decompiled bytecode (<InlineCode>shard -d</InlineCode>) and see a generated
    <InlineCode>&lt;MethodName&gt;k__AsyncStateMachine_N</InlineCode> class.
  </Bullet>
  <Bullet>
    You are debugging a suspended task and want to understand how the runtime resumes it through the
    event loop.
  </Bullet>
  <Bullet>
    You are optimizing allocation: every async method allocates one state-machine instance and one
    task/value-task instance.
  </Bullet>
</ul>

<H2>Remarks</H2>

<H2>The generated state-machine class</H2>

<Prose>
  For each async method, the compiler emits a class named
  <InlineCode>&lt;MethodName&gt;k__AsyncStateMachine_N</InlineCode> that implements
  <InlineCode>IAsyncState</InlineCode>. The class contains the fields needed to resume execution
  after a suspension:
</Prose>

<DocsTable
  headers={['Field', 'Type', 'Purpose']}
  rows={[
    [<InlineCode>_state</InlineCode>, 'int', 'Segment index. 0 is the entry segment; awaitIndex + 1 is the segment that runs after the await completes.'],
    [<InlineCode>_task</InlineCode>, <>'Task or '<InlineCode>ValueTask&lt;T&gt;</InlineCode></>, 'The task returned to the caller. It is completed or faulted when the async method finishes.'],
    [<InlineCode>_outerThis</InlineCode>, 'Enclosing class', 'For instance async methods, a copy of this so member access still works after suspension.'],
    [<InlineCode>_awaiterN</InlineCode>, 'Awaiter type', 'One per await site. Holds the awaiter across the suspension so GetResult can be called on resume.'],
    [<InlineCode>&lt;p&gt;name</InlineCode>, 'Parameter type', 'Lifted parameter. The factory copies each argument into its field.'],
    [<InlineCode>&lt;l&gt;name</InlineCode>, 'Variable type', 'Lifted local variable. Survives across awaits because it lives on the heap.'],
    [<InlineCode>&lt;e&gt;N</InlineCode>, <InlineCode>IEnumerator</InlineCode>, 'For foreach / for-in loops that contain awaits, the enumerator is stored in a field.'],
    [<InlineCode>_currentException</InlineCode>, <InlineCode>RuntimeException</InlineCode>, 'Present only when an await appears inside a catch clause. Preserves the caught exception across the suspension.'],
  ]}
/>

<Prose>
  The class also has an empty <InlineCode>init</InlineCode> constructor (just
  <InlineCode>RETURN</InlineCode>) and a <InlineCode>MoveNext</InlineCode> method that implements
  <InlineCode>IAsyncState.MoveNext</InlineCode>.
</Prose>

<H2>The factory method</H2>

<Prose>
  The original async method is replaced entirely by a factory. Its emitted bytecode performs the
  following steps in order:
</Prose>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Create the state machine.</strong>{' '}
    <InlineCode>NEWOBJECT</InlineCode> allocates the generated class.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Save outer this.</strong> For instance methods, copy the
    original <InlineCode>this</InlineCode> (slot 0) into <InlineCode>_outerThis</InlineCode>.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Copy parameters.</strong> For each lifted parameter, load
    the argument and store it into the matching <InlineCode>&lt;p&gt;name</InlineCode> field.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Create the task.</strong> Allocate a new{' '}
    <InlineCode>Task</InlineCode> or <InlineCode>ValueTask&lt;T&gt;</InlineCode> and store it in{' '}
    <InlineCode>_task</InlineCode>.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Root the task.</strong> Call{' '}
    <InlineCode>InternalRoot</InlineCode> so the GC cannot reclaim the task while it is suspended.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Kick off segment 0.</strong> Call{' '}
    <InlineCode>stateMachine.MoveNext()</InlineCode> synchronously to run up to the first await.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Return the task.</strong> Load <InlineCode>_task</InlineCode>{' '}
    from the state machine and return it to the caller.
  </Bullet>
</ul>

<H2>MoveNext: segment dispatch</H2>

<Prose>
  <InlineCode>MoveNext</InlineCode> is the heart of the lowering. It is emitted as a flat bytecode
  stream with one segment per await site plus the entry segment. At runtime it works like this:
</Prose>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Top-level exception guard.</strong> The whole body is
    wrapped in <InlineCode>ENTER_TRY</InlineCode>. Any unhandled exception calls{' '}
    <InlineCode>task.SetException</InlineCode> and returns.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">State dispatch.</strong> The code loads{' '}
    <InlineCode>_state</InlineCode> and compares it to 0, 1, 2, …, jumping to the matching segment.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Segment entry.</strong> Each segment first restores lifted
    parameters and locals from fields into their MoveNext local slots.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Resume context (segments &gt; 0).</strong> The segment
    re-enters active try regions, re-registers active defers, and calls{' '}
    <InlineCode>_awaiterN.GetResult()</InlineCode>. If resuming inside a catch clause, it restores the
    captured exception into <InlineCode>CurrentException</InlineCode>.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Run user code.</strong> Execution continues from the
    resume point until the next await, return, or end of the method.
  </Bullet>
</ul>

<H2>The bytecode around an await</H2>

<Prose>
  There is no dedicated <InlineCode>AWAIT</InlineCode> opcode. The compiler emits a fixed sequence of
  ordinary instructions at every await site:
</Prose>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Evaluate.</strong> Emit the awaited expression, leaving
    the awaitable on the evaluation stack.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">GetAwaiter.</strong> Call{' '}
    <InlineCode>GetAwaiter()</InlineCode> (or use the awaitable itself as a self-awaiter) and store
    the awaiter in a temporary local.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Store in field.</strong> Copy the awaiter into{' '}
    <InlineCode>this._awaiterN</InlineCode> so it survives suspension.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Fast-path check.</strong> If{' '}
    <InlineCode>_awaiterN.IsCompleted</InlineCode> is true, jump directly to the next segment without
    suspending.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Preserve catch context.</strong> Inside a catch clause,
    load the current exception and store it in <InlineCode>_currentException</InlineCode>.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Set state.</strong> Write{' '}
    <InlineCode>_state = awaitIndex + 1</InlineCode> so the next resume runs the correct segment.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Register continuation.</strong> Call{' '}
    <InlineCode>_awaiterN.OnCompleted(this)</InlineCode>, passing the state machine as the callback.
    The event loop calls <InlineCode>MoveNext</InlineCode> when the operation finishes.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Return.</strong> Exit <InlineCode>MoveNext</InlineCode>,
    unwinding the VM call stack back to the event loop.
  </Bullet>
</ul>

<Callout tone="blue">
  The VM does not understand async/await. Suspension and resumption are implemented with standard
  opcodes such as <InlineCode>CALLMETHODSYMBOL</InlineCode>, <InlineCode>LOADFIELD</InlineCode>,
  <InlineCode>STOREFIELD</InlineCode>, conditional jumps, and <InlineCode>RETURN</InlineCode>.
</Callout>

<H2>Lifting parameters, locals, and enumerators</H2>

<Prose>
  Local variables normally live in the method&apos;s local-slot array, which disappears when the
  frame is popped. Any variable whose value must survive an <InlineCode>await</InlineCode> is
  <strong>lifted</strong> into a field on the state-machine class:
</Prose>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Parameters</strong> become{' '}
    <InlineCode>&lt;p&gt;name</InlineCode> fields. The factory copies arguments into them; each
    segment copies them back into MoveNext local slots at entry.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Locals</strong> become <InlineCode>&lt;l&gt;name</InlineCode>{' '}
    fields. The original variable&apos;s <InlineCode>SlotIndex</InlineCode> is permanently retargeted
    to its MoveNext slot during emission.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Enumerators</strong> from{' '}
    <InlineCode>foreach</InlineCode> / <InlineCode>for..in</InlineCode> loops that contain awaits become
    <InlineCode>&lt;e&gt;N</InlineCode> fields so iteration state survives suspension.
  </Bullet>
</ul>

<Callout tone="blue">
  The <InlineCode>ParameterSlotRemapper</InlineCode> helper temporarily redirects parameter slot
  indices during MoveNext emission, so every <InlineCode>LOADVARIABLE</InlineCode> /{' '}
  <InlineCode>STOREVARIABLE</InlineCode> targets the correct local slot.
</Callout>

<H2>Control flow across awaits</H2>

<Prose>
  After hoisting, every await is a top-level statement. The compiler records the statement that
  follows each await as the <InlineCode>NextStatement</InlineCode> for that site. On resume,
  execution jumps to that statement. If the await is the last statement in a try block, the
  generated code leaves the try region and continues with the code that follows it.
</Prose>

<Prose>
  Loops with awaits are supported, but <InlineCode>break</InlineCode> and{' '}
  <InlineCode>continue</InlineCode> are patched at emission time to target the correct epilogue or
  re-entry label inside the segmented structure. For <InlineCode>foreach</InlineCode> /{' '}
  <InlineCode>for..in</InlineCode> loops, the enumerator is stored in a state-machine field so the
  loop can resume its iteration.
</Prose>

<H2>Try/catch, defer, and exceptions</H2>

<Prose>
  <InlineCode>try</InlineCode> / <InlineCode>catch</InlineCode> blocks inside async methods are
  preserved across suspensions. The compiler records the active try stack at each await site and
  re-emits <InlineCode>ENTER_TRY</InlineCode> instructions when resuming. If an await appears inside
  a catch clause, the caught exception is stored in <InlineCode>_currentException</InlineCode> before
  suspending and restored on resume.
</Prose>

<Prose>
  <InlineCode>defer</InlineCode> works in async methods because the emission pass re-emits all active
  <InlineCode>DEFER</InlineCode> registrations on every resume path, rebuilding the defer stack to
  the correct state before execution continues. Defers run when the scope exits, even after one or
  more await suspensions.
</Prose>

<Callout tone="amber" title="Await inside defer is not supported">
  A <InlineCode>defer</InlineCode> body must not contain an <InlineCode>await</InlineCode>. The
  deferred code runs on scope exit, after the await that triggered the suspension has already
  completed; suspending again inside the deferred body is not supported and produces a compile error.
</Callout>

<H2>Task completion</H2>

<Prose>
  When the async method reaches its end, <InlineCode>MoveNext</InlineCode> transitions the task to
  completed:
</Prose>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    For <InlineCode>Task</InlineCode>, it calls <InlineCode>task.Complete()</InlineCode>.
  </Bullet>
  <Bullet>
    For <InlineCode>ValueTask&lt;T&gt;</InlineCode>, it calls{' '}
    <InlineCode>task.SetResult(default(T))</InlineCode> by default, or the awaited result when the
    last statement is <InlineCode>return await expr;</InlineCode>.
  </Bullet>
  <Bullet>
    If an unhandled exception escapes, the top-level catch handler calls{' '}
    <InlineCode>task.SetException(exception)</InlineCode>.
  </Bullet>
</ul>

<H2>Runtime resumption and GC roots</H2>

<Prose>
  When a libuv callback completes an async operation, the runtime calls{' '}
  <InlineCode>ResumeContinuation</InlineCode>. It reads the continuation off the task, finds the
  state machine&apos;s <InlineCode>MoveNext</InlineCode> method, and invokes it. Because the task was
  rooted by the factory, the state machine and its lifted fields are kept alive by the GC while the
  method is suspended.
</Prose>

<Prose>
  <strong>Common mistake: awaiting inside a conditional expression.</strong> The hoisting pass can
  only lift awaits that appear as top-level statements. Awaiting inside the condition of an{' '}
  <InlineCode>if</InlineCode> or the short-circuiting branch of an operator is currently unsupported
  and reports a compile-time error.
</Prose>

<CodeBlock
  code={`using stdio;
using async;

namespace demo;

public class Program
{
    public static async func GetBoolAsync() -> ValueTask<bool>
    {
        await Task.Delay(10);
        return true;
    }

    public static async func Bad() -> Task
    {
        // ERROR: await is not allowed inside the condition expression.
        // Rewrite it by awaiting into a local first, then testing the local.
        if (await GetBoolAsync())
        {
            println("yes");
        }
    }

    public static async func Good() -> Task
    {
        ready: bool = await GetBoolAsync();
        if (ready)
        {
            println("yes");
        }
    }

    public static func Main() -> void
    {
        task: Task = Good();
        task.Wait();
    }
}`}
  language="csharp"
  filename="await_in_condition.shard"
/>

<Callout tone="amber" title="Unsupported await shapes">
  Awaits nested inside conditional expressions, short-circuiting branches, or{' '}
  <InlineCode>defer</InlineCode> bodies are not supported by the current lowering. Rewrite them so
  the await is a top-level statement assigned to an explicitly typed local.
</Callout>

<H2>Lowered bytecode overview</H2>

<Prose>
  The decompiled outline below shows the shape of the generated code for a single-await async method.
  Addresses and pool indices are illustrative; the actual offsets depend on the method and layout.
</Prose>

<CodeBlock
  code={`; Factory: original async method body is replaced by this.
; It creates the state machine, roots the task, and runs segment 0.
NEWOBJECT   <DelayedHello>k__AsyncStateMachine_0
STOREVAR    temp_stateMachine
NEWOBJECT   Task
STOREVAR    temp_task
LDVAR       temp_stateMachine
LDVAR       temp_task
STOREFIELD  _task
LDVAR       temp_stateMachine
LDFIELD     _task
CALLMETHOD  Task.InternalRoot
LDVAR       temp_stateMachine
CALLMETHOD  <DelayedHello>k__AsyncStateMachine_0.MoveNext
LDVAR       temp_stateMachine
LDFIELD     _task
RETURN

; MoveNext: switches on _state and runs the matching segment.
ENTER_TRY   handler_end
LDVAR       this
LDFIELD     _state
LDC.INT64   0
CEQ
JMP.TRUE    segment_0
LDVAR       this
LDFIELD     _state
LDC.INT64   1
CEQ
JMP.TRUE    segment_1
RETURN

segment_0:
    ; Restore lifted locals/parameters (none in this trivial example).
    ; User code up to the await.
    LDSTR       "before delay"
    CALL        stdio.println

    ; Evaluate the awaitable and get its awaiter.
    LDC.INT64   100
    CALL        Task.Delay
    CALL        Task.GetAwaiter
    STOREVAR    temp_awaiter
    LDVAR       this
    LDVAR       temp_awaiter
    STOREFIELD  _awaiter0

    ; Fast path: if already completed, jump to segment 1.
    LDVAR       this
    LDFIELD     _awaiter0
    CALL        TaskAwaiter.get_IsCompleted
    JMP.TRUE    segment_1

    ; Suspend: set state, register continuation, return.
    LDVAR       this
    LDC.INT64   1
    STOREFIELD  _state
    LDVAR       this
    LDVAR       this
    LDFIELD     _awaiter0
    CALL        TaskAwaiter.OnCompleted
    RETURN

segment_1:
    ; Resume context: consume the previous awaiter.
    LDVAR       this
    LDFIELD     _awaiter0
    CALL        TaskAwaiter.GetResult

    ; Remaining user code.
    LDSTR       "after delay"
    CALL        stdio.println

    ; Normal exit.
    LEAVE_TRY
    JMP         normal_exit

handler_end:
    STOREVAR    ex
    LDVAR       this
    LDFIELD     _task
    LDVAR       ex
    CALL        Task.SetException
    RETURN

normal_exit:
    LDVAR       this
    LDFIELD     _task
    CALL        Task.Complete
    RETURN`}
  language="csharp"
  filename="lowered_overview.txt"
/>

<Callout tone="blue">
  The emitted bytecode uses real opcodes such as <InlineCode>ENTER_TRY</InlineCode>,{' '}
  <InlineCode>LEAVE_TRY</InlineCode>, <InlineCode>CALLMETHOD</InlineCode>, and{' '}
  <InlineCode>STOREFIELD</InlineCode>. The example above is simplified for readability; decompile your
  own program with <InlineCode>shard -d app.shard</InlineCode> to see the exact layout.
</Callout>
