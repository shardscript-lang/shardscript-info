<H2>Summary</H2>

<Prose>
  A <InlineCode>switch</InlineCode> expression evaluates a single <em>scrutinee</em>{' '}
  expression and selects the first arm whose pattern matches. Patterns can be constant values
  (integer, string, boolean, enum), type tests (<InlineCode>is Type</InlineCode>), or type tests
  that bind a variable (<InlineCode>is Type varName</InlineCode>). The discard pattern{" "}
  <InlineCode>{"_"}</InlineCode> acts as a catch-all default arm. Unlike an imperative{" "}
  <InlineCode>switch</InlineCode> statement, every arm produces a value and the whole expression
  evaluates to the chosen arm's value.
</Prose>

<H2>Syntax</H2>

<Prose>
  Write <InlineCode>switch</InlineCode> followed by the scrutinee, then a brace-delimited list
  of arms. Each arm contains a pattern, the fat arrow <InlineCode>=&gt;</InlineCode>, and an
  expression. Arms are separated by commas; the trailing comma after the last arm is optional.
</Prose>

<CodeBlock
  code={`switchValue = switch scrutinee
{
    constantPattern  => expression1,
    is Type          => expression2,
    is Type varName  => expression3,
    _                => defaultExpression,
};`}
  language="csharp"
  filename="switch_expression_syntax.shard"
/>

<H2>Parameters / Arguments</H2>

<DocsTable
  headers={['Part', 'Required', 'Description']}
  rows={[
    ['scrutinee', 'Yes', 'The expression whose value is matched. It is evaluated exactly once.'],
    ['constant pattern', 'Yes, if no type pattern', 'A constant expression compared against the scrutinee using equality. The first matching arm wins.'],
    ['is Type', 'Yes, if no type pattern', 'A type pattern that matches when the scrutinee is an instance of Type or a derived type.'],
    ['is Type varName', 'Yes, if no type pattern', 'A type pattern that matches the same way and binds the casted instance to varName in the arm expression.'],
    ['arm expression', 'Yes', 'The expression that provides the value of the switch expression when its arm is selected.'],
    ['_', 'No', 'The discard pattern. It matches any value and is conventionally written as the last arm.'],
  ]}
/>

<H2>Returns</H2>

<Prose>
  The switch expression returns the value of the expression from the selected arm. The type of
  the switch expression is taken from the first arm, so every arm should produce the same type
  for predictable results.
</Prose>

<H2>Exceptions / Errors</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Missing braces or arrow</strong> — Omitting{' '}
    <InlineCode>{'{'}</InlineCode>, <InlineCode>=&gt;</InlineCode>, or{' '}
    <InlineCode>{'}'}</InlineCode> after an arm pattern produces a parser error.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">No matching arm without default</strong> — If the
    scrutinee does not match any pattern and there is no <InlineCode>{"_"}</InlineCode> arm, the
    result is undefined.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Mismatched arm expression types</strong> — The
    current semantic binder does not reject arms with different expression types. The first
    arm's type becomes the switch expression type, so mixed types can silently produce
    unexpected behavior.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Pattern type mismatch</strong> — Constant patterns are
    not required to match the scrutinee type, but comparing unrelated types (for example,{' '}
    <InlineCode>string</InlineCode> against <InlineCode>int</InlineCode>) typically fails at
    runtime.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Type pattern on non-instance scrutinee</strong> — A
    type pattern such as <InlineCode>is Cat</InlineCode> matches <InlineCode>null</InlineCode> as
    a non-matching case and continues to the next arm. It does not throw.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Binding variable shadows an outer name</strong> — The
    binder rejects an <InlineCode>is Type varName</InlineCode> arm when <InlineCode>varName</InlineCode>{' '}
    conflicts with an existing local or parameter in the enclosing scope.
  </Bullet>
</ul>

<H2>Remarks</H2>

<Prose>
  <strong>Expression, not statement.</strong> A switch expression always yields a value, so it
  can appear anywhere an expression is expected: on the right-hand side of an assignment, as a
  function argument, in a return statement, or nested inside another switch expression.
</Prose>

<Prose>
  <strong>Sequential matching.</strong> Arms are tested in source order and the first matching
  arm is selected. There is no implicit fallthrough; once an arm is selected, its expression is
  evaluated and the switch expression is complete.
</Prose>

<Prose>
  <strong>Constant patterns.</strong> Constant patterns are literal or named values such as
  integer literals, string literals, boolean literals, or enum member accesses. They are compared
  against the scrutinee using equality. The parser accepts arbitrary expressions in a pattern
  position, but only constant patterns are guaranteed to behave as a true match.
</Prose>

<Prose>
  <strong>Type patterns.</strong> A type pattern <InlineCode>is Type</InlineCode> uses the runtime
  type information of the scrutinee. It matches when the scrutinee is an instance of the named
  type or a type derived from it. Interfaces are supported, so <InlineCode>is IDisposable</InlineCode>{' '}
  matches any instance whose type implements the interface. A type pattern does not match{" "}
  <InlineCode>null</InlineCode>; it simply fails and lets a later arm attempt to match.
</Prose>

<Prose>
  <strong>Binding variables.</strong> In <InlineCode>is Type varName</InlineCode>, the binder
  introduces a new local variable <InlineCode>varName</InlineCode> whose type is <InlineCode>Type</InlineCode>{' '}
  inside the corresponding arm expression. The variable holds the scrutinee cast to that type, so
  members available on <InlineCode>Type</InlineCode> can be accessed without an additional cast.
  The variable exists only for the arm it is declared in; it is not visible after the switch
  expression.
</Prose>

<Prose>
  <strong>Pattern arm ordering.</strong> Constant-pattern arms and type-pattern arms can be mixed
  in the same switch expression. Arms are still tested in source order, and the first matching arm
  wins. Place more specific type patterns before less specific ones; for example, put{" "}
  <InlineCode>is Cat</InlineCode> before <InlineCode>is Animal</InlineCode> when both could match.
</Prose>

<Prose>
  <strong>Default arm placement.</strong> The discard pattern <InlineCode>{"_"}</InlineCode> can be
  placed anywhere in the arm list, but conventionally it is written last so the preceding arms
  can match first. If <InlineCode>{"_"}</InlineCode> appears before other arms, those arms are
  unreachable.
</Prose>

<Prose>
  <strong>Single evaluation.</strong> The scrutinee is evaluated exactly once. Store it in a
  local variable first if evaluating it has side effects that you do not want to repeat.
</Prose>

<Prose>
  <strong>Type of the switch expression.</strong> The binder currently uses the type of the
  first arm as the switch expression type. It does not verify that later arms produce the same
  type, so keep all arm expressions homogeneous to avoid subtle type errors.
</Prose>

<Callout tone="amber" title="switch statement status">
  The imperative <InlineCode>switch</InlineCode> statement (with <InlineCode>case</InlineCode>{' '}
  labels, block bodies, and fallthrough control) is planned but not yet implemented. Today, use
  the <InlineCode>switch</InlineCode> expression form shown on this page for constant pattern
  matching.
</Callout>

<Prose>
  <strong>Type patterns and variable bindings.</strong>
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public interface Animal
{
    func Name() -> string;
}

public class Cat : Animal
{
    public func Name() -> string
    {
        return "cat";
    }

    public func Meow() -> string
    {
        return "meow";
    }
}

public class Dog : Animal
{
    public func Name() -> string
    {
        return "dog";
    }

    public func Bark() -> string
    {
        return "woof";
    }
}

public static func MakeSound(a: Animal) -> string
{
    return switch a
    {
        is Cat c => c.Meow(),
        is Dog d => d.Bark(),
        is Animal => "some animal",
        _ => "unknown",
    };
}

public static func Main() -> void
{
    cat: Animal = new Cat();
    dog: Animal = new Dog();

    println(MakeSound(cat));   // meow
    println(MakeSound(dog));   // woof
    println(MakeSound(null));  // unknown
}`}

<Prose>
  <strong>Common mistakes and edge cases.</strong>
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public static func Main() -> void
{
    n: int = 1;

    // The _ pattern is written first, so it catches every value and the
    // later 1 => "one" arm is never reached.
    result: string = switch n
    {
        _ => "default",
        1 => "one",
    };

    println(result);   // default

    // Without a _ default arm, a value that matches no pattern leaves the
    // switch expression with an undefined result.
    //
    // bad: string = switch n { 1 => "one", 2 => "two" };   // undefined for n == 3
}`}
