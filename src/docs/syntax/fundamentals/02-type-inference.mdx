<Prose>
  ShardScript is a <strong>statically typed</strong> language: every value has a type that is known before the program runs. Type inference lets the compiler deduce that type from the initializer expression, so you can write <InlineCode>name := value</InlineCode> instead of spelling out <InlineCode>name: Type = value</InlineCode> every time. The resulting code is shorter, but the type system is just as strict — once the compiler has chosen a type, it never changes.
</Prose>

<H2>Introduction</H2>

<Prose>
  Type inference removes repetitive type annotations for local variables whose type is obvious from the right-hand side. The compiler still builds a complete symbol table with concrete types, emits the same bytecode, and reports the same assignment errors. Inference is purely a source-level convenience; it does not make ShardScript dynamically typed.
</Prose>

<Prose>
  There are two separate ideas that are often both called “inference”:
</Prose>

<Bullet>
  <li><strong>Local-variable inference:</strong> <InlineCode>x := 42</InlineCode> lets the compiler decide that <InlineCode>x</InlineCode> is <InlineCode>int</InlineCode>.</li>
  <li><strong>Generic argument inference:</strong> <InlineCode>Factory.Make(42)</InlineCode> lets the compiler decide that the type parameter <InlineCode>T</InlineCode> is <InlineCode>int</InlineCode>.</li>
</Bullet>

<Prose>
  This article explains both, where each is allowed, and how they interact with method overloads and the special <InlineCode>any</InlineCode> type.
</Prose>

<H2>What it is</H2>

<Prose>
  Local-variable inference uses the declare-assign operator <InlineCode>:=</InlineCode> (sometimes called the “walrus” operator). The grammar is:
</Prose>

<CodeBlock
  code={`identifier := expression;`}
  language="csharp"
  filename="inference_syntax.shard"
/>

<Prose>
  Internally, the parser treats <InlineCode>:=</InlineCode> as a variable declaration whose declared type is <InlineCode>var</InlineCode>. During semantic analysis <InlineCode>var</InlineCode> is represented by the internal <InlineCode>any</InlineCode> placeholder. The binder evaluates the initializer, records the resulting concrete type, and then <strong>replaces</strong> the variable’s type with that concrete type. From that point on the variable behaves exactly as if you had written an explicit annotation.
</Prose>

<Prose>
  The compiler can infer the type from any expression whose type is known:
</Prose>

<DocsTable
  headers={['Initializer', 'Inferred type', 'Notes']}
  rows={[
    [<code>42</code>, 'int', 'Integer literals without a decimal point are int.'],
    [<code>3.14</code>, 'double', 'Floating-point literals are double.'],
    [<code>true</code>, 'bool', 'Boolean literal.'],
    [<code>"hello"</code>, 'string', 'String literal.'],
    [<code>'A'</code>, 'char', 'Character literal.'],
    [<code>[1, 2, 3]</code>, 'int[]', 'Collection literals are arrays when no target type forces another shape.'],
    [<code>1..10</code>, 'Range', 'Range expression.'],
    [<code>new List&lt;int&gt;()</code>, 'List&lt;int&gt;', 'Generic construction with explicit arguments.'],
    [<code>Make()</code>, 'return type of Make', 'Call expressions inherit the callee return type.'],
  ]}
/>

<Prose>
  Because the type is fixed at the declaration, later assignments must match it:
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public static func Main() -> void
{
    count := 10;
    count = 20;          // OK -- count is still int

    // count = "twenty"; // ERROR -- cannot assign string to int
    println(count);
}`}
  language="csharp"
  filename="inference_fixed_type.shard"
/>

<H2>When to use it</H2>

<Prose>
  Use <InlineCode>:=</InlineCode> whenever the initializer already says everything important about the type and the explicit annotation would add noise. Typical places are:
</Prose>

<Bullet>
  <li>Local variables inside methods.</li>
  <li>The initializer of a C-style <InlineCode>for</InlineCode> loop, because it is parsed as a normal statement.</li>
  <li>The iteration variable of <InlineCode>foreach</InlineCode> and <InlineCode>for..in</InlineCode> loops, where the type is inferred from the enumerable or range.</li>
  <li>Generic method calls where the type arguments can be inferred from the arguments.</li>
</Bullet>

<Prose>
  You must still write explicit types in places where there is no initializer expression to infer from:
</Prose>

<DocsTable
  headers={['Location', 'Inference allowed?', 'Reason']}
  rows={[
    [<code>Local variable</code>, 'Yes', 'Initializer expression is available.'],
    [<code>for init statement</code>, 'Yes', 'Parsed as a normal variable statement.'],
    [<code>foreach variable</code>, 'Yes', 'Inferred from IEnumerable&lt;T&gt; or range.'],
    [<code>for..in variable</code>, 'Yes', 'Inferred from range.'],
    [<code>Field</code>, 'No', 'Fields require an explicit type annotation.'],
    [<code>Parameter</code>, 'No', 'Callers must know the expected parameter type.'],
    [<code>Return type</code>, 'No', 'Method contracts are always explicit.'],
    [<code>Property</code>, 'No', 'Property declarations require an explicit type.'],
  ]}
/>

<Callout tone="blue">
  The parser also rejects <InlineCode>var x = ...</InlineCode>. ShardScript does not use the <InlineCode>var</InlineCode> keyword for inference; use <InlineCode>x := ...</InlineCode> instead.
</Callout>

<H2>Remarks</H2>

<Prose>
  The following sections cover the compiler mechanics, edge cases, and interactions with other language
  features that govern type inference.
</Prose>

<H2>How inference works at compile time</H2>

<Prose>
  The semantic binder performs two passes over the declaration:
</Prose>

<Bullet>
  <li>During collection, the variable is created with type <InlineCode>any</InlineCode>.</li>
  <li>During binding, the initializer expression is visited and its type is computed.</li>
  <li>If the variable’s type is <InlineCode>any</InlineCode>, it is replaced by the initializer’s type.</li>
  <li>If the variable already has a concrete type (because you wrote <InlineCode>name: Type = value</InlineCode>), the binder checks assignability instead.</li>
</Bullet>

<Prose>
  This means <InlineCode>:=</InlineCode> is not a special runtime type. The emitted bytecode is identical to an explicit declaration; the compiler simply filled in the annotation for you.
</Prose>

<H2>Numeric literals and widening</H2>

<Prose>
  Integer literals are always <InlineCode>int</InlineCode> and floating-point literals are always <InlineCode>double</InlineCode>. There is no suffix syntax to request <InlineCode>byte</InlineCode> or <InlineCode>char</InlineCode> from a literal. If you need a smaller numeric type, declare it explicitly:
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public static func Main() -> void
{
    i := 42;        // int
    d := 3.14;      // double
    b: byte = 255;  // explicit byte -- cannot be inferred from the literal

    println(i);
    println(d);
    println(b);
}`}
  language="csharp"
  filename="inference_numeric.shard"
/>

<H2>Null initializers</H2>

<Prose>
  Initializing a variable with <InlineCode>null</InlineCode> leaves the compiler without enough information to choose a concrete type. Use an explicit annotation when the value starts as null:
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public class Widget
{
    public Name: string;

    public init(name: string)
    {
        this.Name = name;
    }
}

public static func Main() -> void
{
    // found := null;              // ERROR -- cannot infer type from null
    found: Widget = null;          // OK -- type is explicit

    if (found != null)
    {
        println(found.Name);
    }
    else
    {
        println("not found");
    }
}`}
  language="csharp"
  filename="inference_null.shard"
/>

<H2>Collection and range inference</H2>

<Prose>
  Array literals infer their element type from the first element. All elements must be compatible with that type. An empty array literal <InlineCode>[]</InlineCode> cannot be inferred on its own unless it appears in a context with a known element type:
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public static func Main() -> void
{
    numbers := [10, 20, 30];     // int[]
    range := [1..10];            // int[]; a bracketed range literal is the range itself

    println(numbers.Length);     // 3
    println(range.Length);       // 9

    // empty: int[] = [];        // OK only with an explicit target type
}`}
  language="csharp"
  filename="inference_collections.shard"
/>

<Prose>
  In <InlineCode>foreach</InlineCode> loops, the iteration variable is inferred from the collection’s element type. A range expression yields <InlineCode>int</InlineCode>:
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public static func Main() -> void
{
    foreach (i in 0..3)
    {
        println(i);     // 0, 1, 2  -- i is int
    }

    names := ["one", "two", "three"];
    foreach (name in names)
    {
        println(name);  // name is string
    }
}`}
  language="csharp"
  filename="inference_foreach.shard"
/>

<H2>Generic method inference</H2>

<Prose>
  When you call a generic method without explicit type arguments, the compiler tries to infer each type parameter by matching the method’s parameter types against the argument types you supplied. Inference succeeds only when every type parameter is determined unambiguously:
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public class Factory
{
    public static func Make<T>(value: T) -> Container<T>
    {
        c: Container<T> = new Container<T>();
        c.Value = value;
        return c;
    }
}

public class Container<T>
{
    public Value: T;
}

public static func Main() -> void
{
    c := Factory.Make(42);      // T is inferred as int
    println(c.Value);           // 42

    s := Factory.Make("hi");    // T is inferred as string
    println(s.Value);           // hi
}`}
  language="csharp"
  filename="inference_generic_method.shard"
/>

<Prose>
  If the compiler cannot infer every type parameter, you must supply them explicitly:
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public class Tool
{
    public static func Create<T, U>() -> Pair<T, U>
    {
        return new Pair<T, U>();
    }
}

public class Pair<T, U>
{
    public First: T;
    public Second: U;
}

public static func Main() -> void
{
    // p := Tool.Create();              // ERROR -- T and U have no argument sources
    p: Pair<int, string> = Tool.Create<int, string>();  // OK
    println("created");
}`}
  language="csharp"
  filename="inference_generic_explicit.shard"
/>

<H2>Interplay with method overloads</H2>

<Prose>
  Method overload resolution runs <strong>after</strong> the argument expressions have been typed. That means an inferred local variable already has its concrete type before it is passed to an overloaded method. Overload resolution then picks the most specific matching signature:
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public class Printer
{
    public static func Show(value: int) -> void
    {
        println("int: " + value);
    }

    public static func Show(value: double) -> void
    {
        println("double: " + value);
    }
}

public static func Main() -> void
{
    i := 42;            // int
    d := 3.14;          // double

    Printer.Show(i);    // resolves to Show(int)
    Printer.Show(d);    // resolves to Show(double)
}`}
  language="csharp"
  filename="inference_overloads.shard"
/>

<Prose>
  If you pass an untyped <InlineCode>null</InlineCode> literal directly, overload resolution has no concrete type to match and will fail unless there is an <InlineCode>any</InlineCode> parameter. Assign the null to a typed variable first, or cast it:
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public class Box
{
    public static func Check(value: string) -> void
    {
        if (value == null)
        {
            println("null string");
        }
        else
        {
            println("string: " + value);
        }
    }
}

public static func Main() -> void
{
    s: string = null;
    Box.Check(s);       // OK -- s is typed as string
}`}
  language="csharp"
  filename="inference_overload_null.shard"
/>

<H2>The any fallback</H2>

<Prose>
  ShardScript has an <InlineCode>any</InlineCode> type that bypasses static checking. You can request it explicitly with <InlineCode>x: any = ...</InlineCode>. A variable declared with <InlineCode>:=</InlineCode> never becomes <InlineCode>any</InlineCode> unless the initializer itself evaluates to <InlineCode>any</InlineCode>, which can happen when calling an external or native method whose return type was not specialized.
</Prose>

<Callout tone="amber">
  Relying on <InlineCode>any</InlineCode> disables compile-time type safety and may postpone errors to runtime. Prefer explicit annotations or concrete inferred types in normal code.
</Callout>

<H2>Common mistakes</H2>

<DocsTable
  headers={['Mistake', 'Why it fails', 'Fix']}
  rows={[
    [<code>var x = 10;</code>, "ShardScript does not use 'var'.", <><code>x := 10;</code> or <code>x: int = 10;</code></>],
    [<code>x := null;</code>, 'null has no concrete type.', <><code>x: Widget = null;</code></>],
    [<code>x := 10; x = "ten";</code>, 'Inferred type is int, not string.', 'Use separate variables or a common base type.'],
    [<code>x := [];</code>, 'Empty collection has no element type.', <><code>x: int[] = [];</code></>],
    [<code>Factory.Make();</code>, 'No arguments to infer T from.', <><code>Factory.Make&lt;int&gt;();</code> or provide an argument.</>],
  ]}
/>

<H2>Examples</H2>

<Prose>
  The following program demonstrates inference in a single realistic method, including locals, loops, and generic helpers:
</Prose>

<CodeBlock
  code={`using stdio;
using collections;

namespace demo;

public class Counter
{
    public static func Sum(values: IEnumerable<int>) -> int
    {
        total := 0;

        foreach (value in values)
        {
            total = total + value;
        }

        return total;
    }
}

public static func Main() -> void
{
    numbers := [1, 2, 3, 4, 5];     // int[]
    result := Counter.Sum(numbers); // int, with T inferred from the argument

    for (i := 0; i < result; i++)   // i is int, inferred from the literal 0
    {
        if (i % 2 == 0)
        {
            println(i);             // 0, 2, 4
        }
    }

    println("sum = " + result);     // sum = 15
}`}
  language="csharp"
  filename="inference_complete.shard"
/>

<Prose>
  The next example shows explicit annotations used where inference is impossible, such as fields, null initializers, and generic construction:
</Prose>

<CodeBlock
  code={`using stdio;

namespace demo;

public class Node<T>
{
    public Value: T;
    public Next: Node<T>;

    public init(value: T)
    {
        this.Value = value;
        this.Next = null;
    }
}

public static func Main() -> void
{
    head: Node<string> = new Node<string>("first");
    head.Next = new Node<string>("second");

    current := head;                            // inferred as Node<string>
    while (current != null)
    {
        println(current.Value);
        current = current.Next;
    }
}`}
  language="csharp"
  filename="inference_mixed.shard"
/>

<Callout tone="blue">
  When in doubt, add an explicit annotation. Inference is a convenience, not a requirement, and explicit types often make the intent clearer in complex generic code.
</Callout>
