<H2>Summary</H2>

<Prose>
  The <InlineCode>shard.streams</InlineCode> library (namespace <InlineCode>io</InlineCode>) defines a
  three-tier interface hierarchy — <InlineCode>IStream</InlineCode>, <InlineCode>IReadableStream</InlineCode>,
  and <InlineCode>IWritableStream</InlineCode> — that every byte-oriented stream implementation must
  satisfy. These contracts let you write polymorphic I/O code that works with <InlineCode>MemoryStream</InlineCode>,
  <InlineCode>FileStream</InlineCode>, <InlineCode>SocketStream</InlineCode>, or any future backend without
  depending on a concrete type.
</Prose>

<H2>Syntax</H2>

<Prose>
  All stream interfaces live in the <InlineCode>io</InlineCode> namespace. Concrete stream types are
  declared in their own libraries, but they implement the same <InlineCode>io</InlineCode> interfaces:
</Prose>

<CodeBlock
  code={`using io;

namespace demo;

public static func Main() -> void
{
    // A MemoryStream can be viewed through every abstraction.
    ms := new MemoryStream();

    base: IStream = ms;
    reader: IReadableStream = ms;
    writer: IWritableStream = ms;

    // Cleanup is always expressed through the base interface.
    base.Dispose();
}`}

<H2>Exceptions / Errors</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Cannot access a closed stream</strong> — Calling
    <InlineCode>Read</InlineCode>, <InlineCode>Write</InlineCode>, or <InlineCode>Seek</InlineCode> after
    <InlineCode>Dispose()</InlineCode> or <InlineCode>Close()</InlineCode> throws a runtime exception.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Offset and count must be non-negative</strong> — Both
    <InlineCode>Read</InlineCode> and <InlineCode>Write</InlineCode> reject negative offsets or counts.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Buffer bounds violation</strong> — If <InlineCode>offset + count</InlineCode>{' '}
    exceeds <InlineCode>buffer.Length</InlineCode>, the operation throws rather than silently corrupt memory.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Cannot write to a non-writable stream</strong> — A stream created from
    a read-only byte array (for example, <InlineCode>new MemoryStream(buffer)</InlineCode>) rejects writes.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Cannot seek before the beginning</strong> — <InlineCode>Seek</InlineCode>{' '}
    throws when the resulting position is negative.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Invalid seek origin</strong> — Passing a value other than{' '}
    <InlineCode>Begin</InlineCode>, <InlineCode>Current</InlineCode>, or <InlineCode>End</InlineCode> throws.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Operation canceled</strong> — The cancellation-aware async overloads return
    a faulted task when the <InlineCode>CancellationToken</InlineCode> is already canceled.
  </Bullet>
</ul>

<H2>Remarks</H2>

<Prose>
  <strong>Position and Length are not interface members.</strong> The contracts above intentionally say
  nothing about random access. <InlineCode>Position</InlineCode>, <InlineCode>Length</InlineCode>, and
  <InlineCode>Seek</InlineCode> are provided by seekable concrete types such as{' '}
  <InlineCode>MemoryStream</InlineCode> and <InlineCode>FileStream</InlineCode>. Network-backed streams such as
  <InlineCode>SocketStream</InlineCode> do not support seeking; code that needs random access should accept the
  concrete type or test capabilities before calling <InlineCode>Seek</InlineCode>.
</Prose>

<Prose>
  <strong>Read returns zero at end-of-stream.</strong> A <InlineCode>Read</InlineCode> call may return fewer
  bytes than requested even before EOF (for example, when reading from a socket with a partial packet). The only
  reliable EOF signal is a return value of <InlineCode>0</InlineCode>. Loops that need an exact byte count should
  call <InlineCode>Read</InlineCode> repeatedly until the buffer is filled or EOF is reached.
</Prose>

<Prose>
  <strong>Write is all-or-nothing for MemoryStream.</strong> In-memory writes always copy the full requested
  count, growing the internal buffer as needed. Device-backed streams may buffer internally; call{' '}
  <InlineCode>Flush</InlineCode> or dispose the stream to ensure data is persisted.
</Prose>

<Prose>
  <strong>Dispose is idempotent.</strong> Calling <InlineCode>Dispose()</InlineCode> more than once is safe.
  Disposing a stream through an <InlineCode>IStream</InlineCode>-typed reference also satisfies any wrapper such as
  <InlineCode>StreamReader</InlineCode> or <InlineCode>BinaryReader</InlineCode> that holds the same instance.
</Prose>

<Prose>
  <strong>Async overloads are thin wrappers for in-memory streams.</strong>{' '}
  <InlineCode>MemoryStream.ReadAsync</InlineCode> and <InlineCode>WriteAsync</InlineCode> complete synchronously
  on the caller's thread and return an already-completed <InlineCode>ValueTask</InlineCode> or{' '}
  <InlineCode>Task</InlineCode>. Device-backed streams (file, socket) schedule real asynchronous I/O on the libuv
  event loop and resume the awaiter when the operation completes.
</Prose>

<Callout tone="blue">
  Prefer interface-typed parameters when writing reusable helpers. A function that accepts{' '}
  <InlineCode>IReadableStream</InlineCode> works equally well with files, memory buffers, and sockets without
  introducing coupling to any specific library.
</Callout>

<Callout tone="amber" title="SocketStream is not seekable">
  <InlineCode>SocketStream</InlineCode> implements <InlineCode>IReadableStream</InlineCode> and{' '}
  <InlineCode>IWritableStream</InlineCode>, but it has no <InlineCode>Position</InlineCode>,{' '}
  <InlineCode>Length</InlineCode>, or <InlineCode>Seek</InlineCode> members. Do not write generic code that assumes
  every stream is seekable.
</Callout>

<H2>Examples</H2>

<Prose>
  <strong>Assigning a concrete stream to each abstraction.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using io;

namespace demo;

public static func Main() -> void
{
    // MemoryStream implements all three interfaces plus IDisposable.
    ms := new MemoryStream();

    disposable: IDisposable = ms;
    base: IStream = ms;
    reader: IReadableStream = ms;
    writer: IWritableStream = ms;

    // Write through the writable interface.
    payload: byte[] = [65 as byte, 66 as byte, 67 as byte];
    writer.Write(payload, 0, 3);

    // Dispose through the base interface closes the stream.
    base.Dispose();

    println("assigned and disposed ok");
}`}

<Prose>
  <strong>Reading until end-of-stream with a reusable helper.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using io;

namespace demo;

// A helper that works for any readable stream, not just MemoryStream.
public static func ReadAll(source: IReadableStream) -> byte[]
{
    accumulator := new MemoryStream();
    chunk: byte[] = [0 as byte; 256];

    while (true)
    {
        read: int = source.Read(chunk, 0, 256);
        if (read == 0)
        {
            // EOF reached; no more bytes available.
            break;
        }

        accumulator.Write(chunk, 0, read);
    }

    return accumulator.ToArray();
}

public static func Main() -> void
{
    ms := new MemoryStream();
    ms.Write([72 as byte, 101 as byte, 108 as byte, 108 as byte, 111 as byte], 0, 5);

    // Rewind to the beginning before reading.
    ms.Position = 0;

    all: byte[] = ReadAll(ms);
    println(all.Length);   // 5

    ms.Dispose();
}`}

<Prose>
  <strong>Seeking with SeekOrigin.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using io;

namespace demo;

public static func Main() -> void
{
    ms := new MemoryStream();
    ms.Write([10 as byte, 20 as byte, 30 as byte, 40 as byte], 0, 4);

    // Seek from the beginning to index 2.
    ms.Seek(2, SeekOrigin.Begin);
    println(ms.Position);   // 2

    // Overwrite the byte at index 2.
    ms.Write([99 as byte], 0, 1);

    // Seek two bytes backward from the current position.
    ms.Seek(-2, SeekOrigin.Current);
    println(ms.Position);   // 1

    // Seek one byte backward from the end.
    ms.Seek(-1, SeekOrigin.End);
    println(ms.Position);   // 3

    ms.Dispose();
}`}

<Prose>
  <strong>Asynchronous read and write.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using io;
using async;

namespace demo;

public static async func CopyAsync(source: IReadableStream, target: IWritableStream) -> Task
{
    buffer: byte[] = [0 as byte; 1024];

    while (true)
    {
        read: int = await source.ReadAsync(buffer, 0, 1024);
        if (read == 0)
        {
            // End of input; flush any remaining buffered output.
            break;
        }

        await target.WriteAsync(buffer, 0, read);
    }

    await target.FlushAsync();
}

public static func Main() -> void
{
    src := new MemoryStream();
    src.Write([1 as byte, 2 as byte, 3 as byte], 0, 3);
    src.Position = 0;

    dst := new MemoryStream();

    task := CopyAsync(src, dst);
    Task.Wait(task);

    dst.Position = 0;
    result: byte[] = [0 as byte; 3];
    dst.Read(result, 0, 3);
    println(result[0]);   // 1
    println(result[1]);   // 2
    println(result[2]);   // 3

    src.Dispose();
    dst.Dispose();
}`}

<Prose>
  <strong>Cancellation-aware async operation.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using io;
using async;

namespace demo;

public static async func ReadWithTimeout(source: IReadableStream, buffer: byte[]) -> Task
{
    cts := new CancellationTokenSource();
    cts.CancelAfter(10);   // cancel after 10 milliseconds

    try
    {
        // The cancellation-aware overload checks the token before scheduling I/O.
        read: int = await source.ReadAsync(buffer, 0, buffer.Length, cts.Token);
        println("read " + read + " bytes");
    }
    catch (ex: RuntimeException)
    {
        println("canceled or failed: " + ex.Message);
    }

    cts.Dispose();
}

public static func Main() -> void
{
    ms := new MemoryStream();
    ms.Write([1 as byte, 2 as byte, 3 as byte], 0, 3);
    ms.Position = 0;

    buffer: byte[] = [0 as byte; 256];
    Task.Wait(ReadWithTimeout(ms, buffer));

    ms.Dispose();
}`}

<Prose>
  <strong>Common mistake: reading without checking the returned count.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using io;

namespace demo;

public static func Main() -> void
{
    ms := new MemoryStream();
    ms.Write([65 as byte, 66 as byte], 0, 2);
    ms.Position = 0;

    buffer: byte[] = [0 as byte; 10];

    // WRONG: assumes Read fills the entire buffer.
    // ms.Read(buffer, 0, 10);
    // println(buffer[2]);   // undefined content

    // CORRECT: use the returned count.
    read: int = ms.Read(buffer, 0, 10);
    println(read);   // 2

    i: int = 0;
    while (i < read)
    {
        println(buffer[i]);
        i = i + 1;
    }

    ms.Dispose();
}`}
