<H2>Summary</H2>

<Prose>
  The <InlineCode>shard.http</InlineCode> library exposes the <InlineCode>HttpServer</InlineCode> class in
  the <InlineCode>net</InlineCode> namespace for creating a native HTTP server. It registers route handlers
  that receive the request body as a <InlineCode>string</InlineCode> and return the response body as a
  <InlineCode>string</InlineCode>, then blocks the calling thread while listening for incoming requests.
</Prose>

<H2>Syntax</H2>

<Prose>
  <InlineCode>HttpServer</InlineCode> is instantiated with a parameterless constructor. Routes are registered
  with <InlineCode>Get</InlineCode>, and the server is started with <InlineCode>Listen</InlineCode>.
  <InlineCode>Dispose</InlineCode> stops the listener and releases native resources.
</Prose>

<H2>Exceptions / Errors</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Server is disposed</strong> — Calling{' '}
    <InlineCode>Get</InlineCode> or <InlineCode>Listen</InlineCode> on a disposed server throws a runtime
    exception with the message <InlineCode>"HttpServer: Server is disposed."</InlineCode>
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Handler returned null or threw</strong> — If the callback throws an
    unhandled exception, or if it returns <InlineCode>null</InlineCode>, the server responds with HTTP 500 and
    the error message as <InlineCode>text/plain; charset=utf-8</InlineCode>.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Listen failed to bind</strong> — If the host or port is invalid, or
    if the port is already in use, <InlineCode>Listen</InlineCode> throws a runtime exception from the
    underlying native HTTP library.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Namespace not imported</strong> — The <InlineCode>net</InlineCode>{' '}
    namespace must be imported with <InlineCode>using net;</InlineCode> before{' '}
    <InlineCode>HttpServer</InlineCode> can be referenced.
  </Bullet>
</ul>

<H2>Remarks</H2>

<Prose>
  <strong>Single-method routing.</strong> The current <InlineCode>HttpServer</InlineCode> implementation
  exposes only <InlineCode>Get</InlineCode>. POST, PUT, DELETE, and other HTTP methods are not registered by
  this class. All registered handlers respond to GET requests and receive only the request body as a
  <InlineCode>string</InlineCode>; headers, query strings, and the request method are not passed to the
  callback.
</Prose>

<Prose>
  <strong>Response content type.</strong> The server always serves the handler return value with the content
  type <InlineCode>text/plain; charset=utf-8</InlineCode> and HTTP status 200. There is no API to set custom
  headers or status codes from ShardScript.
</Prose>

<Prose>
  <strong>Blocking listen.</strong> <InlineCode>Listen</InlineCode> starts the native listener on a background
  thread, then pumps the current <InlineCode>ApplicationDomain</InlineCode>'s libuv event loop on the calling
  thread. The call does not return until the server is stopped, which means the server must be shut down from
  another thread, signal handler, or by disposing the instance from a callback.
</Prose>

<Prose>
  <strong>VM thread affinity.</strong> Incoming requests are accepted by httplib worker threads and then
  marshaled onto the domain event loop so that route handlers run on the same VM thread as the rest of the
  program. This avoids concurrency hazards inside the ShardScript runtime.
</Prose>

<Prose>
  <strong>Disposal.</strong> <InlineCode>HttpServer</InlineCode> implements{' '}
  <InlineCode>IDisposable</InlineCode>. Call <InlineCode>Dispose()</InlineCode> to stop the listener, break the
  blocking <InlineCode>Listen</InlineCode> call, and release the native server object and event-loop handle.
  Disposing a server that has already been stopped is safe.
</Prose>

<Callout tone="blue">
  Use <InlineCode>defer server := new HttpServer();</InlineCode> or explicitly call{' '}
  <InlineCode>server.Dispose()</InlineCode> to ensure the native listener is torn down. A server left running
  will keep the process alive.
</Callout>

<Callout tone="amber" title="Not implemented">
  POST, PUT, DELETE, PATCH, and HEAD route registration are not exposed by{' '}
  <InlineCode>shard.http</InlineCode>. Custom response headers, status codes, and query-string access are also
  not implemented.
</Callout>

<H2>Examples</H2>

<Prose>
  <strong>Basic server with a single route.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using net;

namespace demo;

public static func Main() -> void
{
    server: HttpServer = new HttpServer();

    server.Get("/", lambda(requestBody: string) -> string
    {
        return "Hello, ShardScript!";
    });

    println("Listening on http://127.0.0.1:8080");
    server.Listen("127.0.0.1", 8080);

    server.Dispose();
}`}

<Prose>
  <strong>Using a named handler function instead of a lambda.</strong>
</Prose>

<CodeBlock
  code={`using stdio;

public static func GreetHandler(requestBody: string) -> string

    {
        return "Hello, stranger!";
    }

    return "Hello, " + requestBody + "!";
}

public static func Main() -> void
{
    server: HttpServer = new HttpServer();

    server.Get("/greet", GreetHandler);
    server.Get("/greet/default", GreetHandler);

    server.Listen("127.0.0.1", 8080);
    server.Dispose();
}`}

<Prose>
  <strong>Common mistake: calling <InlineCode>Listen</InlineCode> without a way to stop the server.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using net;

namespace demo;

public static func Main() -> void
{
    server: HttpServer = new HttpServer();

    server.Get("/", lambda(requestBody: string) -> string
    {
        return "hello";
    });

    // WRONG: Listen blocks forever. There is no shutdown path.
    // server.Listen("127.0.0.1", 8080);

    // CORRECT: arrange for Dispose to be called later, for example from a
    // signal handler, another thread, or the defer statement shown above.
    server.Listen("127.0.0.1", 8080);
    server.Dispose();
}`}
  language="csharp"
  filename="httpserver_shutdown.shard"
/>
