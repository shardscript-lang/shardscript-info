<H2>Summary</H2>

<Prose>
  The <InlineCode>shard.subprocess</InlineCode> library lets a ShardScript program spawn external
  processes and interact with their <InlineCode>stdin</InlineCode>,{' '}
  <InlineCode>stdout</InlineCode>, and <InlineCode>stderr</InlineCode> streams. This page covers the
  I/O redirection API, blocking read helpers, write helpers, process lifetime management
  (<InlineCode>WaitForExit</InlineCode>, <InlineCode>Kill</InlineCode>), and deterministic cleanup
  via <InlineCode>IDisposable</InlineCode> and <InlineCode>defer</InlineCode>.
</Prose>

<H2>Exceptions / Errors</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Process start failure</strong> —{' '}
    <InlineCode>Process.Start</InlineCode> throws when the executable cannot be found, permission is
    denied, pipe creation fails, or the start-info object is invalid. The native error code is
    surfaced as part of the exception message.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">UseShellExecute not supported</strong> — Setting{' '}
    <InlineCode>ProcessStartInfo.UseShellExecute = true</InlineCode> causes{' '}
    <InlineCode>Process.Start</InlineCode> to throw immediately.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Invalid process handle</strong> — Calling{' '}
    <InlineCode>WaitForExit</InlineCode>, <InlineCode>Kill</InlineCode>,{' '}
    <InlineCode>ReadToEnd</InlineCode>, <InlineCode>ReadErrorToEnd</InlineCode>, or{' '}
    <InlineCode>Write</InlineCode> after the process has been disposed throws.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Stream not redirected</strong> —{' '}
    <InlineCode>ReadToEnd</InlineCode>, <InlineCode>ReadErrorToEnd</InlineCode>, and{' '}
    <InlineCode>Write</InlineCode> throw if the corresponding{' '}
    <InlineCode>RedirectStandard*</InlineCode> flag was not set before the process was started.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Timeout does not kill</strong> —{' '}
    <InlineCode>WaitForExit(ms)</InlineCode> returns <InlineCode>false</InlineCode> on timeout and
    leaves the process running. You must call <InlineCode>Kill</InlineCode> explicitly if you want
    termination.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Orphaned child on parent exit</strong> — If the parent
    exits without calling <InlineCode>Dispose</InlineCode> or <InlineCode>Kill</InlineCode>, the
    child may continue running independently of the parent.
  </Bullet>
</ul>

<H2>Remarks</H2>

<Prose>
  <strong>Redirection is configured before launch.</strong> The runtime creates OS pipes only when
  the corresponding <InlineCode>RedirectStandardOutput</InlineCode>,{' '}
  <InlineCode>RedirectStandardError</InlineCode>, or{' '}
  <InlineCode>RedirectStandardInput</InlineCode> field is set to <InlineCode>true</InlineCode> on
  the <InlineCode>ProcessStartInfo</InlineCode> object. Attempting to read or write a stream that
  was not redirected produces a runtime error.
</Prose>

<Prose>
  <strong>Blocking reads collect the entire stream.</strong>{' '}
  <InlineCode>ReadToEnd</InlineCode> and <InlineCode>ReadErrorToEnd</InlineCode> read in 4096-byte
  chunks until the pipe closes, then call <InlineCode>WaitForExit</InlineCode> internally to reap
  the child and update <InlineCode>ExitCode</InlineCode>. Because these calls block the calling
  thread until the child closes its end of the pipe, they are not suitable for interactive or
  streaming scenarios where you need to read while the process is still running.
</Prose>

<Prose>
  <strong>Writing to stdin.</strong> <InlineCode>Write</InlineCode> converts the supplied string to
  UTF-8 and writes it through <InlineCode>std::fwrite</InlineCode>, followed by an explicit{' '}
  <InlineCode>std::fflush</InlineCode>. <InlineCode>WriteLine</InlineCode> performs the same write
  and then appends a single <InlineCode>\n</InlineCode> byte. If you need to signal end-of-input to
  a child that reads until EOF, close the pipe by disposing the <InlineCode>Process</InlineCode>{' '}
  instance or by letting the deferred disposal run.
</Prose>

<Prose>
  <strong>Waiting and timeouts.</strong> The parameterless <InlineCode>WaitForExit()</InlineCode>{' '}
  blocks until the child terminates and returns the OS exit code. The timed overload polls the
  native <InlineCode>subprocess_alive</InlineCode> function in a loop with 10 ms sleeps. A
  negative timeout is treated as an indefinite wait. On timeout the method returns{' '}
  <InlineCode>false</InlineCode> and does <em>not</em> terminate the child.
</Prose>

<Prose>
  <strong>Kill behavior.</strong> <InlineCode>Kill</InlineCode> calls the native terminate function
  (<InlineCode>TerminateProcess</InlineCode> on Windows, <InlineCode>SIGTERM</InlineCode> on POSIX),
  sets <InlineCode>ExitCode</InlineCode> to <InlineCode>-1</InlineCode>, and marks the process as
  exited. Calling <InlineCode>Kill</InlineCode> on an already-exited process is a no-op.
</Prose>

<Prose>
  <strong>IDisposable and defer.</strong> <InlineCode>Process</InlineCode> implements{' '}
  <InlineCode>IDisposable</InlineCode>. The recommended pattern is to declare the variable with{' '}
  <InlineCode>defer</InlineCode>: <InlineCode>defer p: Process = Process.Start(...)</InlineCode>.
  This guarantees that <InlineCode>Dispose</InlineCode> runs when the variable goes out of scope,
  whether by normal return, early return, or exception. <InlineCode>Dispose</InlineCode> calls the
  native destroy function, closes all pipe handles, frees the underlying{' '}
  <InlineCode>subprocess_s</InlineCode> structure, and nulls the handle field. Calling{' '}
  <InlineCode>Dispose</InlineCode> multiple times is safe.
</Prose>

<Callout tone="blue">
  The native subprocess layer always enables asynchronous I/O internally so that blocking reads
  can drain the pipe reliably. You do not need to set any async flag manually; just enable the
  specific <InlineCode>RedirectStandard*</InlineCode> flags you need.
</Callout>

<H2>Examples</H2>

<Prose>
  <strong>Capture stdout and stderr separately.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using process;

namespace demo;

public static func Main() -> void
{
    info: ProcessStartInfo = new ProcessStartInfo();
    info.FileName = "cmd.exe";
    info.Arguments = "/c echo stdout message & echo stderr message >&2";
    info.RedirectStandardOutput = true;
    info.RedirectStandardError = true;
    info.CreateNoWindow = true;

    defer p: Process = Process.Start(info);

    outText: string = p.ReadToEnd();
    errText: string = p.ReadErrorToEnd();

    println("stdout: " + outText);
    println("stderr: " + errText);
    println("exit code: " + p.ExitCode);
}`}

  filename="subprocess_capture.shard"
/>

<Prose>
  <strong>Feed input to a child process.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using process;

namespace demo;

public static func Main() -> void
{
    info: ProcessStartInfo = new ProcessStartInfo();
    info.FileName = "cmd.exe";
    info.Arguments = "/c sort";
    info.RedirectStandardInput = true;
    info.RedirectStandardOutput = true;
    info.CreateNoWindow = true;

    defer p: Process = Process.Start(info);

    // Send three lines to the sort utility.
    p.WriteLine("cherry");
    p.WriteLine("apple");
    p.WriteLine("banana");

    // Closing stdin signals EOF; defer will dispose the process at scope exit.
    sorted: string = p.ReadToEnd();

    println("sorted output:");
    println(sorted);
    println("exit code: " + p.ExitCode);
}`}
  language="csharp"
  filename="subprocess_stdin.shard"
/>

<Prose>
  <strong>Enforce a timeout and kill a long-running process.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using process;

namespace demo;

public static func Main() -> void
{
    // On Windows this command sleeps for about 5 seconds.
    defer p: Process = Process.Start("cmd.exe", "/c ping 127.0.0.1 -n 6 > nul");

    finished: bool = p.WaitForExit(250);
    if (!finished)
    {
        println("Timeout reached — terminating process.");
        p.Kill();
    }
    else
    {
        println("Process finished on time.");
    }

    println("Has exited: " + p.HasExited);
    println("Exit code: " + p.ExitCode);
}`}
  language="csharp"
  filename="subprocess_timeout.shard"
/>

<Prose>
  <strong>Check exit status after capturing output.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using process;

namespace demo;

public static func Main() -> void
{
    info: ProcessStartInfo = new ProcessStartInfo();
    info.FileName = "cmd.exe";
    info.Arguments = "/c exit 42";
    info.RedirectStandardOutput = true;
    info.CreateNoWindow = true;

    defer p: Process = Process.Start(info);

    output: string = p.ReadToEnd();
    code: int = p.WaitForExit();

    if (code != 0)
    {
        println("Command failed with exit code " + code);
    }
    else
    {
        println("Command succeeded");
    }

    println("Captured output: '" + output + "'");
}`}

<Callout tone="amber" title="Common mistake: reading after dispose">
  Do not call <InlineCode>ReadToEnd</InlineCode> or <InlineCode>Kill</InlineCode> after the deferred
  <InlineCode>Process</InlineCode> variable has gone out of scope. The handle is released on scope
  exit, and subsequent member access throws. Keep all reads, writes, and waits inside the same
  scope as the <InlineCode>defer</InlineCode> declaration.
</Callout>

  <strong>Environment variables and working directory.</strong>
