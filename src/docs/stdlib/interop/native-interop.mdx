<H2>Summary</H2>

<Prose>
  The <InlineCode>shard.cinterop</InlineCode> standard library exposes the namespace{' '}
  <InlineCode>interop</InlineCode> with three static classes —{' '}
  <InlineCode>NativeLibrary</InlineCode>, <InlineCode>Marshal</InlineCode>, and{' '}
  <InlineCode>NativeCall</InlineCode> — for loading shared native libraries, allocating
  and reading or writing unmanaged memory, and invoking raw C function pointers from
  ShardScript.
</Prose>

<H2>Exceptions / Errors</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Library load failure</strong> —{' '}
    <InlineCode>NativeLibrary.Load</InlineCode> throws a runtime exception when the
    operating system cannot load the library. The message includes the Windows error
    code or the POSIX <InlineCode>dlerror</InlineCode> text.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Null library handle</strong> — Passing zero
    to <InlineCode>NativeLibrary.GetFunction</InlineCode> throws a runtime exception.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Null function pointer</strong> — Every{' '}
    <InlineCode>NativeCall</InlineCode> method throws a runtime exception when the
    function address is zero.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Null pointer access</strong> — Marshal read,
    write, and string-conversion methods throw a runtime exception when the supplied
    pointer is zero and the operation length is non-zero.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Namespace import required</strong> — The{' '}
    <InlineCode>interop</InlineCode> namespace must be imported with{' '}
    <InlineCode>using interop;</InlineCode>. Without it the static classes are not
    visible.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Mismatched return family</strong> — Using the
    wrong <InlineCode>Call*</InlineCode> overload for the C function signature produces
    undefined behavior, including truncated pointer values or corrupted floating-point
    results.
  </Bullet>
</ul>

<H2>Remarks</H2>

<Prose>
  <strong>Platform loaders.</strong> On Windows, <InlineCode>NativeLibrary.Load</InlineCode>{' '}
  calls <InlineCode>LoadLibraryW</InlineCode> with the wide path you supply. On Linux it
  calls <InlineCode>dlopen</InlineCode> with <InlineCode>RTLD_NOW | RTLD_LOCAL</InlineCode>{' '}
  after narrowing the path to a multibyte string. Library search order follows the
  operating-system rules: the application directory, the PATH on Windows, and
  LD_LIBRARY_PATH on Linux.
</Prose>

<Prose>
  <strong>Symbol names.</strong> <InlineCode>NativeLibrary.GetFunction</InlineCode>{' '}
  narrows the export name to ASCII bytes before calling{' '}
  <InlineCode>GetProcAddress</InlineCode> or <InlineCode>dlsym</InlineCode>. Unicode
  names outside the ASCII range may fail to resolve even when the export exists.
</Prose>

<Prose>
  <strong>Memory ownership.</strong> Buffers returned by{' '}
  <InlineCode>StringToAnsi</InlineCode> and <InlineCode>StringToUnicode</InlineCode> are
  allocated with the C runtime allocator and must be released with{' '}
  <InlineCode>Marshal.Free</InlineCode>. Failing to free them leaks native memory. The
  <InlineCode>defer</InlineCode> statement is the recommended way to pair allocation and
  cleanup.
</Prose>

<Prose>
  <strong>Typed reads and writes are unchecked.</strong> The{' '}
  <InlineCode>Marshal.Read*</InlineCode> and <InlineCode>Marshal.Write*</InlineCode>{' '}
  families perform a raw <InlineCode>memcpy</InlineCode> at the computed byte address.
  They do not validate the allocation bounds, alignment, or type. Reading past the end
  of an allocation produces undefined behavior.
</Prose>

<Prose>
  <strong>String encoding.</strong> <InlineCode>StringToAnsi</InlineCode> and{' '}
  <InlineCode>StringFromAnsi</InlineCode> use the active ANSI code page on Windows
  (<InlineCode>CP_ACP</InlineCode>) and the current locale multibyte encoding on Linux.
  <InlineCode>StringToUnicode</InlineCode> and{' '}
  <InlineCode>StringFromUnicode</InlineCode> use NUL-terminated UTF-16, matching the
  Win32 <InlineCode>LPCWSTR</InlineCode> layout.
</Prose>

<Prose>
  <strong>Calling convention and ABI.</strong> <InlineCode>NativeCall</InlineCode> relies
  on the platform C ABI. The integer/pointer families pass every argument as a raw
  64-bit word, which matches the integer and pointer register layout on common 64-bit
  platforms. <InlineCode>CallDouble</InlineCode> passes and returns{' '}
  <InlineCode>double</InlineCode> values through floating-point registers. There is no
  support for selecting <InlineCode>stdcall</InlineCode>, <InlineCode>cdecl</InlineCode>,
  or other conventions, and no support for variadic functions.
</Prose>

<Prose>
  <strong>Pointer arithmetic.</strong> <InlineCode>Marshal.Add</InlineCode> interprets
  the offset as bytes. Adding <InlineCode>Marshal.IntPtrSize</InlineCode> advances by one
  pointer slot, and adding two advances by one UTF-16 code unit when iterating a Unicode
  buffer.
</Prose>

<Callout tone="blue">
  Always pair <InlineCode>NativeLibrary.Load</InlineCode> with{' '}
  <InlineCode>NativeLibrary.Free</InlineCode> and pair every native string allocation
  with <InlineCode>Marshal.Free</InlineCode>. Use <InlineCode>defer</InlineCode> so
  cleanup runs even when an exception is thrown.
</Callout>

<Callout tone="amber" title="Not implemented">
  The <InlineCode>Marshal.Alloc(size)</InlineCode> overload registered by the runtime
  does not match its native callback, which expects two arguments. Do not rely on this
  overload for native allocation. Allocate buffers through{' '}
  <InlineCode>StringToAnsi</InlineCode>/<InlineCode>StringToUnicode</InlineCode> or host
  bindings until a corrected overload is exposed. Struct, union, and array marshalling,
  calling-convention selection, and variadic native calls are also not exposed.
</Callout>

<Prose>
  <strong>Common mistake: using the wrong NativeCall return family.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using interop;

namespace demo;

public static func Main() -> void
{
    lib: nint = NativeLibrary.Load("mylib.dll");
    defer NativeLibrary.Free(lib);

    getHandle: nint = NativeLibrary.GetFunction(lib, "GetHandle");
    if (getHandle == 0 as nint)
    {
        println("GetHandle not found");
        return;
    }

    // WRONG: Call reads only a 32-bit return value and sign-extends it.
    // On a 64-bit platform this truncates a pointer.
    // truncated: int = NativeCall.Call(getHandle);

    // CORRECT: the C function returns a pointer, so use CallN.
    handle: nint = NativeCall.CallN(getHandle);
    println("handle: " + handle);
}`}
  language="csharp"
  filename="interop_wrong_family.shard"
/>
