<H2>Summary</H2>

<Prose>
  <InlineCode>Queue&lt;T&gt;</InlineCode> and <InlineCode>Stack&lt;T&gt;</InlineCode> are generic
  reference types in the <InlineCode>shard.collections</InlineCode> library.
  <InlineCode>Queue&lt;T&gt;</InlineCode> stores elements in first-in, first-out (FIFO) order;
  <InlineCode>Stack&lt;T&gt;</InlineCode> stores elements in last-in, first-out (LIFO) order.
  Both support insertion, removal, inspection, counting, membership testing, and
  <InlineCode>foreach</InlineCode> enumeration by implementing <InlineCode>IEnumerable&lt;T&gt;</InlineCode>.
</Prose>

<H2>Syntax</H2>

<Prose>
  Both types are declared with a single type parameter <InlineCode>T</InlineCode> and are
  instantiated through the parameterless constructor.
</Prose>

<CodeBlock
  code={`using stdio;
using collections;

namespace demo;

public static func Main() -> void
{
    // FIFO queue for pending work items.
    queue: Queue<int> = new Queue<int>();

    // LIFO stack for undo history.
    stack: Stack<string> = new Stack<string>();

    println(queue.Count);   // 0
    println(stack.Count);   // 0
}`}

<H2>Exceptions / Errors</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Empty queue</strong> — Calling{' '}
    <InlineCode>Queue.Dequeue()</InlineCode> or <InlineCode>Queue.Peek()</InlineCode> when{' '}
    <InlineCode>Count == 0</InlineCode> throws a runtime exception with the message "queue is empty".
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Empty stack</strong> — Calling{' '}
    <InlineCode>Stack.Pop()</InlineCode> or <InlineCode>Stack.Peek()</InlineCode> when{' '}
    <InlineCode>Count == 0</InlineCode> throws a runtime exception with the message "stack is empty".
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Type mismatch</strong> — Pushing, enqueuing, or searching with a
    value that is not assignable to <InlineCode>T</InlineCode> fails during semantic analysis.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Null reference</strong> — Calling an instance method on a{' '}
    <InlineCode>null</InlineCode> collection reference throws at runtime.
  </Bullet>
</ul>

<H2>Remarks</H2>

<Prose>
  <strong>Storage and growth.</strong> Both collections are backed by a resizable array.
  The initial capacity is zero; the first insertion allocates capacity <InlineCode>4</InlineCode>,
  and the array doubles each time it becomes full. The queue implementation compacts the array
  and resets <InlineCode>_head</InlineCode> to <InlineCode>0</InlineCode> during growth so that
  enqueue stays amortized <InlineCode>O(1)</InlineCode>. Removing elements does not shrink the
  array; call <InlineCode>Clear()</InlineCode> to release storage.
</Prose>

<Prose>
  <strong>Equality in <InlineCode>Contains</InlineCode>.</strong> The collection walks its elements
  and compares each against the supplied value. Primitives, characters, booleans, and strings are
  compared by value. For all other reference types, equality is reference identity: two distinct
  object instances are never equal even if their fields match.
</Prose>

<Prose>
  <strong>Enumeration order.</strong> A queue enumerates from head to tail, matching the order in
  which elements would be dequeued. A stack enumerates from top to bottom, matching the order in
  which elements would be popped. Both use lightweight value-type enumerators
  (<InlineCode>QueueEnumerator&lt;T&gt;</InlineCode> and <InlineCode>StackEnumerator&lt;T&gt;</InlineCode>)
  that read from the live source collection. Modifying the collection during enumeration is not
  supported and may skip, repeat, or unexpectedly terminate elements.
</Prose>

<Callout tone="blue">
  <InlineCode>Count</InlineCode> is a read-only property, not a method. Access it with{' '}
  <InlineCode>queue.Count</InlineCode> and <InlineCode>stack.Count</InlineCode> — no parentheses are
  needed.
</Callout>

<Callout tone="amber">
  Only the parameterless constructor is available. There is no capacity constructor, no{' '}
  <InlineCode>TrimExcess</InlineCode>, and no <InlineCode>TryDequeue</InlineCode> /{' '}
  <InlineCode>TryPop</InlineCode> helper in the current release.
</Callout>

<H2>Examples</H2>

<Prose>
  <strong>Basic FIFO queue.</strong>
</Prose>

<CodeBlock
  code={`using stdio;
using collections;

namespace demo;

public static func Main() -> void
{
    queue: Queue<int> = new Queue<int>();

    queue.Enqueue(10);
    queue.Enqueue(20);
    queue.Enqueue(30);

    println(queue.Count);      // 3
    println(queue.Peek());     // 10

    while (queue.Count > 0)
    {
        println(queue.Dequeue()); // 10, 20, 30
    }

    println(queue.Count);      // 0
}`}

<Prose>
  <strong>Enumeration order.</strong> A queue yields elements in enqueue order; a stack yields
  elements from the top down.
</Prose>

<CodeBlock
  code={`using stdio;
using collections;

namespace demo;

public static func Main() -> void
{
    queue: Queue<char> = new Queue<char>();
    queue.Enqueue('A');
    queue.Enqueue('B');
    queue.Enqueue('C');

    print("queue: ");
    foreach (ch in queue)
    {
        print(ch);   // ABC
    }
    println("");

    stack: Stack<char> = new Stack<char>();
    stack.Push('A');
    stack.Push('B');
    stack.Push('C');

    print("stack: ");
    foreach (ch in stack)
    {
        print(ch);   // CBA
    }
    println("");
}`}
  language="csharp"
  filename="queue_stack_enumeration.shard"
/>

<Prose>
  <strong>Edge case: empty collection operations.</strong> Always check <InlineCode>Count</InlineCode>{' '}
  before calling <InlineCode>Pop</InlineCode>, <InlineCode>Dequeue</InlineCode>, or{' '}
  <InlineCode>Peek</InlineCode>, or handle the resulting runtime exception.
</Prose>

<CodeBlock
  code={`using stdio;
using collections;

namespace demo;

public static func Main() -> void
{
    queue: Queue<int> = new Queue<int>();

    // Safe: guard before removing.
    if (queue.Count > 0)
    {
        println(queue.Dequeue());
    }
    else
    {
        println("queue is empty — skipping dequeue");
    }

    // Alternative: catch the runtime exception.
    try
    {
        queue.Dequeue();
    }
    catch (ex: RuntimeException)
    {
        println("caught dequeue on empty queue");
    }

    queue.Enqueue(42);
    queue.Clear();
    println(queue.Count); // 0
}`}
  language="csharp"
  filename="queue_stack_empty.shard"

<Prose>
  <strong>Common mistakes.</strong>
</Prose>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Using <InlineCode>Length</InlineCode> instead of{' '}
    <InlineCode>Count</InlineCode>.</strong> Queues and stacks expose <InlineCode>Count</InlineCode>;
    <InlineCode>Length</InlineCode> belongs to arrays and <InlineCode>List&lt;T&gt;</InlineCode>.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Assuming a stack enumerates in insertion order.</strong>{' '}
    <InlineCode>foreach</InlineCode> on a <InlineCode>Stack&lt;T&gt;</InlineCode> walks from the top
    down, which is the same order as repeated <InlineCode>Pop()</InlineCode> calls.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Modifying while enumerating.</strong> Do not push, pop,
    enqueue, or dequeue inside the body of a <InlineCode>foreach</InlineCode> over the same
    collection.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Calling <InlineCode>Dequeue</InlineCode> or{' '}
    <InlineCode>Pop</InlineCode> without checking <InlineCode>Count</InlineCode>.</strong> On an
    empty collection this throws a runtime exception.
  </Bullet>
</ul>
