<H2>Summary</H2>

<Prose>
  The <InlineCode>shard.debug</InlineCode> namespace and the companion{' '}
  <InlineCode>ProgramDisassembler</InlineCode> C++ class provide two complementary ways to inspect a
  ShardScript program: the <InlineCode>-d</InlineCode> (<InlineCode>--decompiled</InlineCode>) CLI flag
  prints the compiled bytecode of every source-defined method, while the{' '}
  <InlineCode>Debug</InlineCode> static class exposes runtime heap and stack snapshots from inside
  running ShardScript code.
</Prose>

<H2>Syntax</H2>

<Prose>
  <strong>Command-line disassembly.</strong> Pass <InlineCode>-d</InlineCode> or{' '}
  <InlineCode>--decompiled</InlineCode> instead of running the program:
</Prose>

<CodeBlock
  code={`shard -d hello.shard
shard --decompiled hello.shard`}
  language="text"
  filename="cli.txt"
/>

<Prose>
  <strong>C++ host integration.</strong> Include <InlineCode>&lt;shard/compilation/ProgramDisassembler.hpp&gt;</InlineCode>{' '}
  and call either overload:
</Prose>

<CodeBlock
  code={`shard::ProgramDisassembler disassembler;

// Disassemble the whole program image starting at its entry point.
disassembler.Disassemble(std::wcout, programVirtualImage);

// Disassemble a single method symbol.
disassembler.Disassemble(std::wcout, methodSymbol);`}
  language="cpp"
  filename="host_disassembler.cpp"
/>

<Prose>
  <strong>Runtime inspection from ShardScript.</strong> Call the static members on the{' '}
  <InlineCode>Debug</InlineCode> class after importing <InlineCode>debug</InlineCode>:
</Prose>

<CodeBlock
  code={`using stdio;
using debug;

namespace demo;

public static func Main() -> void
{
    PrintStackFrameInfo();
    PrintGcInfo();
}`}
  language="csharp"
  filename="runtime_inspection.shard"
/>

<H2>Exceptions / Errors</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Compilation failure</strong> —{' '}
    <InlineCode>-d</InlineCode> still runs the full compiler pipeline. Lexical, syntactic, or
    semantic errors are reported before any bytecode is printed.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Missing entry point</strong> — When calling{' '}
    <InlineCode>Disassemble(std::wostream&amp;, ProgramVirtualImage&amp;)</InlineCode> on an image with no{' '}
    <InlineCode>EntryPoint</InlineCode>, the disassembler writes{' '}
    <InlineCode>; Error: No EntryPoint found in ProgramVirtualImage.</InlineCode>
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">External or empty methods</strong> — Native/external methods
    and methods with no bytecode emit a comment instead of an instruction stream.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">GC concurrency hazard</strong> —{' '}
    <InlineCode>PrintGcInfo</InlineCode> reads the heap vector without synchronization. Calling it
    during GC activity can produce inconsistent output.
  </Bullet>
</ul>

<H2>Remarks</H2>

<Prose>
  <strong>What <InlineCode>-d</InlineCode> actually prints.</strong> The interpreter's decompile mode
  compiles every source file, then iterates over all <InlineCode>MethodSymbol</InlineCode> entries in
  the semantic model. Only methods whose <InlineCode>HandleType</InlineCode> is{' '}
  <InlineCode>Body</InlineCode> and whose declaring compilation unit originated from a source file are
  printed. Compiler-generated async state-machine methods (named{' '}
  <InlineCode>k__AsyncStateMachine_...</InlineCode>) are also included even though they have no
  source node.
</Prose>

<Prose>
  <strong>Method header format.</strong> Each method begins with a framed header:
</Prose>

<CodeBlock
  code={`; ============================================================
;  DISASSEMBLY: demo.Program.Main
; ============================================================
;  Handle:     body
;  Access:     public static
;  Return:     Void
;  Parameters: ()
;  Declared:   demo.Program
;  Locals:     0
;  Variables:  0
; ============================================================`}
  language="text"
  filename="method_header.txt"
/>

<Prose>
  <strong>Instruction format.</strong> Each line contains a 16-bit hex offset prefixed with{' '}
  <InlineCode>SS_</InlineCode>, a right-aligned mnemonic, and operands:
</Prose>

<CodeBlock
  code={`SS_0000:   ldc.bool    false
SS_0003:   jmpf        SS_003F
SS_000D:   ldstr       pool[0]
SS_0017:   call        stdio.println`}
  language="text"
  filename="instruction_lines.txt"
/>

<Prose>
  <strong>Color output.</strong> The disassembler detects whether the output stream is{' '}
  <InlineCode>std::wcout</InlineCode>. If so, it emits ANSI color codes for offsets (gray), mnemonics
  (cyan), and operands (yellow). Redirecting to a file disables colors automatically.
</Prose>

<Callout tone="blue">
  The CLI prints <strong>all</strong> source-defined methods, not just the entry point. This is useful
  for inspecting compiler-generated async state machines, lambda bodies, and helper methods.
</Callout>

<H2>Examples</H2>

<Prose>
  <strong>Disassembling a simple conditional.</strong>
</Prose>

<CodeBlock
  code={`using stdio;

namespace test;

public class Program
{
    public static func Main() -> void
    {
        if (false)
        {
            println("if branch");
        }
        else
        {
            println("else branch");
        }

        println("after");
    }
}`}
  language="csharp"
  filename="if_else.shard"
/>

<Prose>Run <InlineCode>shard -d if_else.shard</InlineCode> to produce:</Prose>

<CodeBlock
  code={`; ============================================================
;  DISASSEMBLY: test.Program.Main
; ============================================================
;  Access:      public static
;  Return:      Void
;  Parameters:  ()
;  Locals:      0
;  Variables:   0
; ============================================================

; Offset    Opcode      Arguments
; --------  -----------  -----------------------------------------
SS_0000:   ldc.bool    false          ; push the condition
SS_0003:   jmpf        SS_003F        ; if false -> skip the then-branch
SS_000D:   ldstr       pool[0]        ; "if branch"
SS_0017:   call        stdio.println
SS_0021:   jmp         SS_003F        ; else-branch fallthrough
SS_002B:   ldstr       pool[10]       ; "else branch"
SS_0035:   call        stdio.println
SS_003F:   ldstr       pool[20]       ; "after"
SS_0049:   call        stdio.println`}
  language="text"
  filename="if_else_disassembly.txt"
/>

<Prose>
  Notice how the compiler emits a forward <InlineCode>jmpf</InlineCode> to skip the then-branch, an
  unconditional <InlineCode>jmp</InlineCode> to skip the else-branch after the then-branch runs, and
  string-pool indices for each literal.
</Prose>

<H2>Common Mistakes</H2>

<ul className="space-y-2 text-text-secondary">
  <Bullet>
    <strong className="text-text-primary">Expecting <InlineCode>-d</InlineCode> to run the program.</strong>{' '}
    The flag compiles and prints bytecode only. Side effects in <InlineCode>Main</InlineCode> do not
    execute.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Reading absolute offsets as stable identifiers.</strong>{' '}
    Offsets change whenever the source, compiler version, or standard-library headers change. Do not
    hard-code them in tooling.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Trusting <InlineCode>unknown</InlineCode> operands.</strong>{' '}
    An <InlineCode>unknown</InlineCode> opcode means the disassembler does not know how many bytes to
    decode, so the rest of the method may be misaligned.
  </Bullet>
  <Bullet>
    <strong className="text-text-primary">Calling <InlineCode>PrintGcInfo</InlineCode> in hot paths.</strong>{' '}
    It walks the entire heap and writes to stdout. Use it as a diagnostic checkpoint, not in tight
    loops.
  </Bullet>
</ul>

<H2>Internal Mechanics</H2>

<div className="space-y-5">
  <div className="bg-[#1A1A2E] border border-[#3A3A50] rounded-card p-5">
    <div className="flex items-center gap-3 mb-3">
      <span className="inline-flex items-center justify-center w-6 h-6 rounded-full bg-accent-blue text-white text-xs font-jetbrains font-semibold">1</span>
      <strong className="text-text-primary text-sm">CLI to Disassembler Pipeline</strong>
    </div>
    <Prose>
      <InlineCode>ShardUtilities::ParseArguments</InlineCode> sets{' '}
      <InlineCode>ShowDecompile = true</InlineCode> and <InlineCode>RunProgram = false</InlineCode>.
      After <InlineCode>compiler.Compile()</InlineCode> succeeds, the interpreter iterates the symbol
      table, skips external/native methods, and calls{' '}
      <InlineCode>ProgramDisassembler::Disassemble(std::wcout, method)</InlineCode> for each body.
    </Prose>
  </div>

  <div className="bg-[#1A1A2E] border border-[#3A3A50] rounded-card p-5">
    <div className="flex items-center gap-3 mb-3">
      <span className="inline-flex items-center justify-center w-6 h-6 rounded-full bg-accent-blue text-white text-xs font-jetbrains font-semibold">2</span>
      <strong className="text-text-primary text-sm">ByteCodeDecoder</strong>
    </div>
    <Prose>
      The disassembler builds a <InlineCode>ByteCodeDecoder</InlineCode> over the method's{' '}
      <InlineCode>ExecutableByteCode</InlineCode> vector and advances one opcode at a time. Each opcode
      case absorbs its specific operands (integers, symbol pointers, jump targets, string-pool
      indices) so the next iteration starts on the next instruction boundary.
    </Prose>
  </div>

  <div className="bg-[#1A1A2E] border border-[#3A3A50] rounded-card p-5">
    <div className="flex items-center gap-3 mb-3">
      <span className="inline-flex items-center justify-center w-6 h-6 rounded-full bg-accent-blue text-white text-xs font-jetbrains font-semibold">3</span>
      <strong className="text-text-primary text-sm">External Methods Have No Bytecode</strong>
    </div>
    <Prose>
      Methods backed by a native C++ callback (such as most of <InlineCode>shard.math</InlineCode>)
      have <InlineCode>HandleType::External</InlineCode>. The disassembler prints their function
      pointer and returns instead of decoding instructions.
    </Prose>
  </div>
</div>
